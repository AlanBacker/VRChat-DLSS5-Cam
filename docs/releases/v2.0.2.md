Stable release with fixes and small additions over v2.0.1. A computer that runs v2.0.1 runs v2.0.2 as it is: the settings file, the presets, the MCP tools and the command line are unchanged, and a program on either update channel offers this version by itself.

## Fixes

- **The depth view comes back after a switch of the depth source.** With the depth view open, switching the depth source from the estimator to *Flat* or *Zero* and back left the view black until the program was started again: the still picture had already used its two re-runs for the first start of the estimator, so the estimate that arrived after the estimator's restart was never shown. The re-runs are now counted per start of the estimator, and an estimator that was parked while the depth view was off starts again when the view is turned back on.
- **The depth network runs only when something uses it.** DLSS 5 itself takes only the picture and the motion vectors (NVIDIA's statement, confirmed here: a flat, a gradient and a zero depth give byte-identical neural-pass output on an RTX 5090). The network (about 400 MB of memory and a DirectML warm-up) is now loaded for DLAA or super resolution, whose DLSS feature takes the depth, and for the depth view, and stopped again when those are off. A DLSS 5-only capture of a still picture no longer waits for it. The *Depth* source's tip and status line say which passes use the depth, and the overlay's depth line reads *Not used* while none does (it used to read *Zero*, which once meant a fault).
- **A second window on the same settings folder no longer empties the log.** A `log.txt` another process still holds open cannot be renamed at start; it is now continued instead of truncated, so the earlier session's lines stay.
- **Scripted runs leave the crash notice alone.** A run ended by its script (`--process`, `--exit-after`, `--headless`) writes no session marker and shows no notice; a marker it finds stays for the next windowed session to report, with the right log. A process that was given the crashed one's process id again (this program included) is no longer taken for it.

## New

- **A notice when the graphics driver is too old.** The bundled DLSS 5 runtime needs GeForce driver 616.56 or newer; on an older one the neural pass does not start. The program now checks the driver at every start and, when it is older, says so in a notice with the graphics card's name, the installed and the required version and NVIDIA's download page (**Download driver** opens it and leaves the notice up, so the version to look for stays in view). *Don't show again* turns the notice off and *Check the graphics driver at start* in *About* turns it back on; the DLSS 5 section keeps a warning line until the driver is updated. The rest of the program works on the old driver, and a batch run only logs the warning.
- **Logs are kept.** `log.txt` is no longer emptied at start: the previous sessions stay as `log-1.txt` to `log-5.txt` next to it.
- **A notice after a crash.** When the previous session did not end in an orderly way (a crash, a kill, a power cut), the next start keeps its log as `log-crash.txt` and says so in a dialog with **Report on GitHub** (an issue form prefilled with the version, edition, graphics card, driver and system, plus the crash record when there is one), **Open log folder** and **Close**. The About section has the same **Report a problem** button. Scripted runs show no dialog.
- **Issue forms on GitHub** in English, Chinese, Japanese and Korean, for bug reports and feature requests, with links to the four READMEs. The version they ask for is at the top of *About*.
- **Release notes in your language.** The update window shows a release's notes in the interface's language (English, Chinese, Japanese or Korean); a release without a translation shows the English text.
