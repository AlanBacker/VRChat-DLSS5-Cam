Processed files can be saved next to their source, and the NVIDIA optical flow now reads the frame it is given. A computer that runs v2.1.0 runs v2.2.0 as it is: the presets, the MCP tools and the command line are unchanged, and the settings file only gains the new switch (`outputToSource`).

## New

- **Save next to the source file.** A switch in the *Capture* section: with it on, a processed picture or video is written into the folder of the file it came from instead of the capture folder, so a round trip from Photoshop, Darktable or a video editor ends where it started. The folder box above is dimmed while the switch is on. Photos from the live camera still go to the capture folder, which is why the switch is not shown for the live source, and `--process <folder>` on the command line still writes into the folder it names. Over MCP the key is `outputToSource`; `capture.folder` in the status reports the folder the current source would be saved to, and the reply of `vdc_process` says `nextToSource` when the batch was spread over the sources' folders. (GitHub issue #4.)

## Fixes

- **The NVIDIA optical flow was one frame late.** The engine used to be driven through its D3D11 interface, which gives no signal when a pass has finished; the vectors the program read were still the previous frame's, so every frame was denoised with the motion of the frame before it. On footage with repeated frames, as variable-rate screen recordings have, that put full motion on still frames and none on moving ones, and the DLSS 5 result wobbled and flickered more with *NVIDIA* optical flow than with *FSR*. The engine is now driven through its D3D12 interface, where each pass is ordered against the graphics queue with fence points, and every frame is denoised with its own vectors. The GeForce drivers this program needs all offer that interface; a driver without it falls back to the FSR optical flow as before.
