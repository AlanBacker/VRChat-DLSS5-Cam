The Radeon edition installs DLSS-NR-on-AMD again, and the program gains a notice channel from this repository. A computer that runs v2.2.0 runs v2.2.1 as it is: the presets, the MCP tools and the command line are unchanged, and the settings file only gains the record of dismissed notices (`noticesDismissed`).

## Fixes

- **DLSS-NR-on-AMD could not be installed.** Since 17 October DLSS-NR-on-AMD ships its releases as NeuralHub, a different installer with a different layout on disk, and the Radeon edition, which looked up the latest release, found no `dlssnr_on_amd_setup.exe` in it: the start-up check failed with *the latest release carries no dlssnr_on_amd_setup.exe*, and the Install button could not install (GitHub issue #7). The program now works with one named release, **v0.2.17**, the last one it was tested with: the look-up asks for it, the Install button fetches it, and the DLSS 5 section shows it next to the installed release, saying so when the installation is older or newer. An installation made with an earlier release keeps working. Support for NeuralHub will come in a later version.

## New

- **Notices from the repository.** At start, by the same route as the update check (GitHub itself or the chosen mirror site), the program reads `notice.json` from this repository and shows the notices that apply to its edition and version as a card at the top of the sidebar and on the *Get started* page, with *Details* and *Dismiss*. A dismissed notice stays away. The channel carries word that cannot wait for a release, such as a change at DLSS-NR-on-AMD. The release the Radeon edition installs is read from `port.json` the same way, so it can be moved in the repository without a new version.
