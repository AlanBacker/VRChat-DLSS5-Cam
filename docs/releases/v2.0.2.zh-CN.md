正式版，在 v2.0.1 的基础上修正了一些问题，并增加了几项小功能。能运行 v2.0.1 的电脑可以直接运行 v2.0.2：设置文件、预设、MCP 工具和命令行都没有变化，两个更新通道上的程序都会主动提示这个版本。

## 修正

- **切换深度来源后，深度视图能恢复显示。** 打开深度视图时，把深度来源从估计器切换到*平面*或*零*再切回来，视图会一直黑屏，直到重启程序：静态图片的两次重新处理在估计器第一次启动时就已用完，估计器再次启动后送来的深度结果便再也没有显示出来。现在重新处理按估计器的每次启动分别计数；深度视图关闭期间停下的估计器，会在重新打开深度视图时再次启动。
- **深度网络只在需要时运行。** DLSS 5 本身只接收画面和运动矢量（这是 NVIDIA 的说法，我们也实测确认：在 RTX 5090 上，平面、渐变和零深度得到的神经渲染输出逐字节相同）。因此，深度网络（约占 400 MB 内存，还需要一次 DirectML 预热）现在只在 DLAA 或超分辨率（它们的 DLSS 功能会读取深度）以及深度视图需要时加载，这些都关闭后随即停止。只开 DLSS 5 时，保存静态图片不再需要等待深度网络。*深度*选项的提示和深度估计器的状态会说明哪些处理会用到深度；没有处理用到深度时，叠加信息中的深度一行显示*未使用*（以前显示的是*零*，而它过去表示出了故障）。
- **再开一个使用同一设置文件夹的窗口，不会再清空日志。** 另一个进程仍在使用的 `log.txt` 无法在启动时重命名；现在程序会接着往里写，而不是清空它，之前那次运行的记录得以保留。
- **脚本运行不再干扰崩溃提示。** 由脚本结束的运行（`--process`、`--exit-after`、`--headless`）不写入运行标记，也不显示提示；它发现的标记会原样保留，留给下一次带窗口的运行附上正确的日志来报告。进程 ID 会被系统重复分配，碰巧沿用了崩溃进程 ID 的进程（包括本程序自身）不再被误认作那个进程。

## 新增

- **显卡驱动过旧时的提醒。** 附带的 DLSS 5 运行库需要 616.56 或更新的 GeForce 驱动，驱动更旧时神经渲染无法启动。程序现在每次启动都会检查驱动，过旧时弹出提示，列出显卡名称、已安装和所需的驱动版本以及 NVIDIA 的下载页面（**下载驱动** 会打开该页面，提示仍留在屏幕上，方便对照要找的版本）。*不再显示*可关闭提示，*关于*中的*启动时检查显卡驱动*可重新开启；驱动更新之前，DLSS 5 分节会一直保留一行警告。程序的其他功能在旧驱动上照常工作，命令行批处理只在日志中记下这条警告。
- **日志会保留下来。** 启动时不再清空 `log.txt`：之前几次运行的日志以 `log-1.txt` 至 `log-5.txt` 保存在它旁边。
- **崩溃后的提示。** 上一次运行没有正常结束时（崩溃、被强制结束、断电），下一次启动会把那次的日志保存为 `log-crash.txt`，并弹出对话框说明情况，提供 **到 GitHub 反馈**（打开已填好版本、版本类型、显卡、驱动和系统的 issue 表单，有崩溃记录时一并附上）、**打开日志文件夹** 和 **关闭** 三个按钮。“关于”分节中也有同样的 **反馈问题** 按钮。脚本运行时不弹出对话框。
- **GitHub 上的 issue 表单**，有英语、中文、日语和韩语四种语言，分为问题反馈和功能建议两类，并附有四份 README 的链接。表单要求填写的版本号显示在*关于*的顶部。
- **以你的语言显示发布说明。** 更新窗口按界面语言（英语、简体中文、日语或韩语）显示版本的发布说明；没有译文的版本显示英文原文。
