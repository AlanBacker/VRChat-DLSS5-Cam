# VRChat DLSS5 Cam

[English](../README.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · **한국어**

VRChat DLSS5 Cam은 VRChat 카메라의 화면을 가져와 GeForce RTX 카드에서 **DLSS 5 뉴럴 렌더링**으로 처리하고,
결과를 무손실 PNG 사진으로 저장합니다. 디스크에 있는 이미지와 동영상도 하나씩 또는 일괄로 똑같이 처리할 수
있습니다. 일반적인 Windows 프로그램이므로 VRChat에 아무것도 주입하지 않으며 모드도 필요 없습니다.

## 무엇을 할 수 있나요

- **실시간 카메라.** DLSS 5를 거친 VRChat Stream 카메라 화면을 실시간으로 보여 주고, VRChat이 앞에 있을 때도
  동작하는 단축키(`Ctrl+Alt+P`)로 PNG 사진을 저장합니다.
- **디스크의 이미지와 동영상.** 스크린샷이나 녹화 파일을 창에 끌어다 놓고 슬라이더를 조정한 뒤 결과를 저장합니다.
  이미지는 PNG로, 동영상은 MP4(H.264 / HEVC, 오디오 유지) 또는 PNG 시퀀스로 저장됩니다.
- **여러 파일 한 번에.** 여는 파일은 모두 미리보기 아래의 라이브러리에 들어갑니다. 일부 또는 전부를 선택해 한 번에
  처리할 수 있으며, 파일마다 공통 설정을 쓰거나 개별 설정을 줄 수 있습니다.
- **진짜 DLSS 5 가이던스.** 뉴럴 네트워크는 NVIDIA Optical Flow의 모션 벡터와 Depth Anything V2의 깊이 맵을
  받으므로, 동영상과 실시간 카메라가 게임에서처럼 처리됩니다. 선택적인 DLAA 패스가 먼저 가장자리를 정리합니다.
- **쉬운 비교.** 와이프, 나란히 보기, 원본 보기를 지원하며, 마우스 휠로 확대하고 드래그로 이동합니다.
- **일상적인 사용을 위한 설계.** 다크·라이트 테마(기본은 Windows 설정을 따름), 모든 설정의 실행 취소와 다시 실행,
  4개 언어(English, 简体中文, 日本語, 한국어), 별도 스레드에서 실행되는 부드러운 인터페이스, 스크립트 실행을 위한
  명령줄을 제공합니다.

## 필요한 것

| | |
|---|---|
| Windows | Windows 10 21H2 또는 Windows 11, 64비트 |
| 그래픽 카드 | NVIDIA GeForce RTX. **RTX 50** 시리즈는 일반 런타임으로 뉴럴 패스를 실행합니다. **RTX 40 / 30 / 20**은 수정된 런타임 빌드가 필요합니다(다음 행 참고). 일반 빌드에서는 앱이 실패를 보고하고 뉴럴 패스 없이 계속 동작합니다. |
| DLSS 5 런타임 | 직접 준비한 `nvngx_dlssnr.dll`. **이 프로젝트에는 포함되어 있지 않으며, 이 프로젝트가 다운로드하지도 않습니다.** 파일은 [RenoDX Discord 서버](https://discord.com/invite/renodx)에서 공유되며, RTX 50 시리즈가 아닌 카드용 수정 빌드도 그곳에서 구할 수 있습니다. 그 서버는 RenoDX 프로젝트의 것이며 이 프로젝트의 Discord가 **아닙니다**. 이 프로젝트에는 자체 Discord 서버가 없습니다. |
| VRChat | Stream 카메라에 *Spout Stream* 옵션이 있는 모든 빌드(데스크톱 또는 VR). 실시간 카메라에만 필요합니다. |
| 동영상 파일 | Windows Media Foundation(Windows에 포함). N / KN 에디션은 *Media Feature Pack*이 필요하며, HEVC 파일은 Microsoft Store의 *HEVC 비디오 확장*이 필요할 수 있습니다. |

## 빠른 시작

1. [최신 릴리스](https://github.com/AlanBacker/VRChat-DLSS5-Cam/releases/latest)에서 `VRChatDLSS5Cam-win64.zip`을 내려받아 원하는 위치에 압축을 풉니다.
2. `nvngx_dlssnr.dll`을 그 폴더의 `VRChatDLSS5Cam.exe` 옆에 복사합니다. (나중에 *DLSS 5 뉴럴 렌더링 → 런타임 경로*에서 파일을 지정할 수도 있습니다.)
3. VRChat에서 **카메라**를 열고 **Stream** 모드로 전환한 뒤, 카메라 설정에서 **Spout Stream**을 켭니다.
4. `VRChatDLSS5Cam.exe`를 실행합니다. DLSS 5가 적용된 카메라 화면이 미리보기에 나타나고, *DLSS 5(DLSSNR) 사용* 스위치 옆의 배지가 *동작 중*으로 표시됩니다.
5. VRChat에서 구도를 잡고 **Ctrl+Alt+P**(또는 *촬영* 버튼)를 누릅니다. PNG는 `Pictures\VRChat DLSS5 Cam`에 저장됩니다.

실시간 카메라 팁

- 스트림 해상도는 VRChat이 결정합니다. 더 선명한 입력을 원하면 VRChat의 `config.json`에서 `camera_spout_res_width` / `camera_spout_res_height`를 높이세요. 앱이 자동으로 맞춥니다.
- 사용 중인 카드에서 뉴럴 패스가 실시간 미리보기에 너무 느리면 DLSS 5 섹션의 *촬영 시에만 뉴럴 패스 실행*을 켜세요. 그러면 미리보기에는 원본 화면이 표시되고, 촬영할 때마다 사진을 위해서만 뉴럴 패스가 실행됩니다.
- *표시* 섹션의 *처리 속도 상한*은 초당 처리하는 카메라 프레임 수를 제한하여 GPU를 VRChat에 여유 있게 남겨 둡니다.

## 디스크의 이미지와 동영상

이미지나 동영상을 창에 끌어다 놓거나, *소스* 섹션의 *이미지 열기…* / *동영상 열기…*를 사용하세요. 화면이
미리보기에 나타나고 모든 슬라이더가 바로 적용됩니다. **처리 후 PNG 저장**(이미지) 또는 **처리 후 동영상 저장**(동영상)이나
단축키를 누르면 결과가 사진과 같은 곳에 `<name>_DLSS5_<w>x<h>.png`, `.mp4` 또는 PNG 프레임이 담긴 폴더로
기록됩니다.

동영상의 경우 미리보기 아래의 컨트롤로 파일을 전체 파이프라인을 거쳐 재생·일시정지하고, 한 프레임씩 이동하며,
탐색 바 위의 커서 위치에 있는 프레임을 작은 그림으로 보여 줍니다. *여기를 시작점으로* / *여기를 끝점으로*는
처리(그리고 오디오)를 한 구간으로 제한하고, *전체 동영상*은 이를 해제합니다. 기본적으로 출력은 원본을 따릅니다:
같은 코덱, 프레임 속도, 비트레이트. *원본 영상 규격에 맞추기*를 끄면 H.264, HEVC 또는 PNG 시퀀스와 비트레이트를
직접 고를 수 있습니다. *촬영* 섹션은 현재 설정으로 파일 처리에 대략 얼마나 걸릴지 보여 줍니다.

## 여러 파일 한 번에 처리

열거나 끌어다 놓은 모든 파일은 미리보기 아래의 **라이브러리**에 들어갑니다(*파일 추가…*와 *폴더 추가…*로 더 추가할
수 있습니다). 썸네일을 클릭하면 그 파일을 미리 보며 슬라이더를 조정할 수 있습니다. 파일 선택은 썸네일 위를
드래그하거나, 각 썸네일의 체크박스, Ctrl+클릭과 Shift+클릭, 또는 전체 선택 **Ctrl+A**로 합니다. 그런 다음
*선택 항목 처리* 또는 *모두 처리*를 누르면 파일이 차례로 처리됩니다. 각 썸네일의 막대가 진행률을 보여 주며
처리 후에도 상태가 남아 있습니다.

썸네일에서 마우스 오른쪽 버튼을 누르면 메뉴가 열립니다: 탐색기에서 파일 표시, 라이브러리에서 제거, 또는 별도 창에서
**그 파일만의 DLSS 5 매개변수** 설정. 여러 파일을 선택한 상태에서는 같은 메뉴에 *N개 파일의 개별 매개변수…*가
나타나 모든 파일의 값을 한 번에 설정하며, 이후 각 파일이 자신의 값을 유지합니다.

## 화면 둘러보기

- **세 섹션이 일상적인 작업을 담당합니다:** *소스*(무엇이 들어오는지), *DLSS 5 뉴럴 렌더링*(어떻게 보이는지),
  *촬영*(어디로 가는지). DLSS 5 섹션의 *고급* 스위치는 톤·구조 슬라이더, 출력 블렌드, 프레임 가이던스, DLAA,
  타이머를 표시하거나 숨깁니다.
- **비교**는 와이프(미리보기의 핸들을 드래그), 나란히 보기, 원본으로 할 수 있습니다. 미리보기 위에서 마우스 휠을
  굴리면 커서를 중심으로 확대/축소되고, 드래그하면 이동하며, 더블클릭하면 창 맞춤 보기로 돌아갑니다.
- 설정의 모든 변경은 **Ctrl+Z** / **Ctrl+Y** 또는 상단 바의 두 화살표로 **실행 취소와 다시 실행**할 수 있습니다.
- **다크 또는 라이트.** *표시* 섹션의 *테마*: *시스템*은 Windows의 앱 색상 설정을 따르며, *다크*나 *라이트*를
  직접 고를 수도 있습니다.
- **사이드바**는 가장자리의 손잡이 뒤로 밀어 숨길 수 있습니다. 파일을 처리하는 동안에는 잠기며 *취소*를
  제공합니다.

| 소스 | 저장 형식 / 비트레이트 / 오디오 유지 | *원본 영상 규격에 맞추기*가 꺼진 경우: *MP4 (H.264)*, *MP4 (HEVC)* 또는 *PNG 시퀀스*, 인코더 비트레이트(5–200 Mbit/s), 오디오 트랙 복사 여부. |
| 소스 | 하드웨어 디코딩 | 동영상을 GPU에서 디코딩합니다. 파일의 색이 이상하거나 열리지 않으면 끄세요. |
| 소스 | 페이퍼 화이트 / 하이라이트 압축 | 부동소수점(HDR) Spout 텍스처일 때만 표시됩니다: 뉴럴 패스 전에 적용되는 노출 기준과 부드러운 하이라이트 롤오프. |
| DLSS 5 | DLSS 5(DLSSNR) 사용 | 뉴럴 패스를 켜거나 끕니다. 끄면 런타임을 해제하고, 켜면 파일에서 다시 불러옵니다. |
| DLSS 5 | 런타임 경로 / 다시 불러오기 | `nvngx_dlssnr.dll`의 위치. *다시 불러오기*는 파일을 다시 불러옵니다. |
| DLSS 5 | 호스트 방식 | *직접(signed snippet)*: `nvngx_dlssnr.dll`을 직접 호스팅합니다. *NGX 코어*: NGX 런타임을 통해 기능을 생성합니다. |
| DLSS 5 | 프리셋 / 스타일 | 런타임에 전달하는 렌더 프리셋(0–3)과 스타일(기본 / 내추럴 / 시네마틱). |
| DLSS 5 | 강도 | 뉴럴 패스의 전체 강도, 0–2. 1까지는 런타임 자체의 강도이고, 1을 넘으면 앱이 뉴럴 결과와 원본의 차이를 증폭합니다(아티팩트가 과장될 수 있음). 0이면 화면을 그대로 둡니다. |
| DLSS 5 | 글로벌 톤 강도 / 로컬 톤 강도 | 글로벌 및 로컬 톤 강도, 0–2. 1을 넘을 때의 규칙은 위와 같습니다(1을 넘는 강도 중 가장 높은 값이 배율이 됩니다). |
| DLSS 5 | 로컬 구조 강도 / 피부 구조 강도 | 디테일 강화, 0–2. 1을 넘을 때의 규칙은 같습니다. 피부 구조는 런타임 기본값으로 둘 수 있습니다. |
| DLSS 5 | 자동 마스크 / UI 보정 | 자동 피사체 마스크, UI 안전 처리. |
| DLSS 5 | 촬영 시에만 뉴럴 패스 실행 | 실시간 사용에는 너무 느린 카드용: 미리보기는 뉴럴 패스를 우회하고, 촬영 시 먼저 새 프레임 16장에 뉴럴 패스를 실행한 뒤 저장합니다. 정지 이미지에는 영향이 없습니다. |
| DLSS 5 | 입력 노출 / 톤 전달 강도 / 색 강도 | 출력 블렌드. 입력 노출(0.25–4배)은 네트워크가 보는 화면을 배율 조정하며 이후 되돌려집니다. 톤 전달 강도와 색 강도(0–2)는 뉴럴 패스가 바꾼 밝기와 색이 출력에 얼마나 반영되는지를 정합니다. 1 / 1이면 뉴럴 결과를 그대로 재현하고, 0이면 원본을 유지합니다. |
| DLSS 5 | 그림자 강도 / 하이라이트·글로우 강도 | 출력 블렌드, 0–2: 뉴럴 패스가 어둡게 만든 변화와 밝게 만든 변화가 각각 출력에 얼마나 반영되는지. 1 / 1 = 렌더링 그대로. |
| DLSS 5 | 뉴럴 패스 해상도 | 축소한 화면(입력의 25–100 %)에서 뉴럴 패스를 실행하고 그 변화를 확대하여 전체 해상도 화면에 더합니다. 값을 낮추면 GPU 부하가 줄지만 가장 미세한 디테일은 사라집니다. 뉴럴 업스케일 중에는 사용되지 않습니다. |
| 프레임 가이던스 | 모션 벡터 | NVIDIA Optical Flow(정방향/역방향 일관성 검사 포함), GPU 블록 매칭, 또는 없음. |
| 프레임 가이던스 | 깊이 | AI 추정(DirectML의 Depth Anything V2 Small, 갱신 간격과 네트워크 해상도 조정 가능), 평면, 그라데이션, 또는 0. |
| 프레임 가이던스 | 장면 전환 시 자동 초기화 | 장면 전환 시 시간 이력을 지웁니다. 기본값은 꺼짐. |
| DLAA 프리패스 | 사용 / 프리셋 | 뉴럴 렌더링 전 네이티브 해상도에서의 선택적 DLSS 안티앨리어싱 패스. |
| 촬영 | 저장 폴더 / 투명도(알파) 유지 / 원본 프레임도 저장 / 전역 단축키 / 자동 촬영 간격 | 사진과 동영상을 어디에 어떻게 저장할지. |
| 촬영 | 예상 처리 시간 | 현재 설정으로 열린 이미지나 동영상을 처리하는 데 걸리는 대략적인 시간. 처리할 때마다 보정됩니다. |
| 표시 | 테마 | *시스템*(Windows를 따름), *다크* 또는 *라이트*. |
| 표시 | 비교 / 창에 맞춤 / 확대 / 수직 동기화 / 오버레이 / 라이브러리 표시 | 미리보기 옵션. |
| 표시 | 처리 속도 상한 | 실시간 카메라: 초당 최대 이 수만큼의 프레임만 처리하고 나머지는 건너뜁니다. 0 = 모든 프레임. |

설정은 `%LOCALAPPDATA%\VRChatDLSS5Cam\settings.ini`에 저장되며, 로그는 같은 폴더의 `log.txt`입니다.

## 문제 해결

- **"VRChat Spout 스트림 대기 중…"** – VRChat의 Stream 카메라에서 *Spout Stream*을 켜세요. 카메라가 열려 있어야 합니다. 다른 Spout 송신자는 *Spout 송신자* 상자에 표시됩니다.
- **"nvngx_dlssnr.dll을 찾을 수 없습니다"** – 런타임을 `VRChatDLSS5Cam.exe` 옆에 복사하거나 DLSS 5 섹션에서 경로를 선택하세요.
- **뉴럴 렌더링 실패** – RTX 40 / 30 / 20에서 일반 런타임을 쓰는 경우 예상된 동작입니다. 그 빌드에는 RTX 50용 코드만 들어 있으며, 앱이 오류 아래에 그렇게 알려 줍니다. RenoDX Discord 서버에서 수정 빌드를 구하세요(*필요한 것* 참고. 이 프로젝트와는 무관합니다). 그 외의 경우 일부 런타임 빌드는 더 새로운 드라이버가 필요합니다. `log.txt`에서 NGX 결과 코드를 확인하고 *프리셋* 0과 *NGX 코어* 방식을 시도해 보세요.
- **뉴럴 패스는 동작 중인데 화면이 검거나 변화가 없음** – 앱은 모든 뉴럴 프레임을 입력과 비교하며, 런타임이 성공을 보고하면서 검은 화면이나 변화 없는 화면을 내놓으면 경고합니다(`log.txt`: "DLSSNR output check"). DLSS 5를 껐다가 다시 켜서 새로 시작하세요. 그래도 계속되면 그 런타임 빌드는 이 GPU에서 화면을 만들지 못하는 것입니다. (*강도*가 0이면 화면에 변화가 없는 것이 정상이며 경고도 표시되지 않습니다.)
- **앱이 시작되지 않음 / 바로 종료됨** – `%LOCALAPPDATA%\VRChatDLSS5Cam\`을 열어 `log.txt`(마지막 줄이 실패한 단계)와 `crash.txt`를 확인하세요. 이슈에는 두 파일을 모두 첨부해 주세요.
- **NGX 초기화 안 됨 / DLAA 지원 안 됨** – NGX 런타임에는 NVIDIA GPU와 최신 드라이버가 필요합니다. DLSS 5는 *직접(signed snippet)* 방식으로 계속 동작합니다.
- **깊이 추정기 사용 불가** – `onnxruntime.dll`, `onnxruntime_providers_shared.dll`, `DirectML.dll`, `models\depth_anything_v2_small_fp16.onnx`가 실행 파일 옆에 있어야 합니다(모두 릴리스 패키지에 포함). 추정기가 준비될 때까지 앱은 0 깊이를 사용하며, 상태는 *프레임 가이던스* 아래에 표시됩니다.
- **옵티컬 플로우 사용 불가** – `log.txt`에 "NVOF unavailable, falling back to block matching"이 보이면 GeForce 드라이버를 업데이트하세요. 그때까지는 블록 매칭이 사용됩니다. *프레임 가이던스* 아래의 상태 점이 현재 사용 중인 소스를 보여 줍니다.
- **동영상 미리보기가 검게 보임** – 많은 영상이 검은 화면에서 페이드인으로 시작합니다. 미리보기는 그런 프레임을 건너뛰고, 표시 중인 프레임이 여전히 어두우면 화면 아래에 알려 줍니다. 탐색 바나 화살표 키로 앞으로 이동하세요.
- **동영상 파일이 열리지 않음 / 인코더 없음** – 지원 형식은 Windows에 설치된 코덱에 따라 다릅니다. HEVC 파일에는 *HEVC 비디오 확장*(Microsoft Store)을, Windows N / KN에는 *Media Feature Pack*을 설치하세요. H.264 인코더가 없으면 출력으로 *PNG 시퀀스*를 고르세요. GPU 디코더가 거부하는 파일은 *하드웨어 디코딩*을 끄면 도움이 됩니다.
- **낮은 프레임률** – DLAA를 끄거나, 깊이 갱신 간격을 늘리거나 깊이 네트워크 해상도를 낮추거나, 뉴럴 패스 해상도를 낮추거나, 처리 속도 상한을 설정하세요. 옵티컬 플로우 그리드는 4 px로 유지하세요(2 px와 1 px는 4K에서 훨씬 무겁습니다). 로그에는 15초마다 각 단계의 비용이 담긴 `Perf:` 줄이 기록됩니다.

## 소스에서 빌드

필요 사항: Visual Studio 2022(MSVC v143, Windows 10 SDK) 및 CMake 3.21 이상.

```powershell
git clone https://github.com/AlanBacker/VRChat-DLSS5-Cam.git
cd VRChat-DLSS5-Cam
cmake -S . -B build -A x64
cmake --build build --config Release --parallel
```

구성 단계에서 NVIDIA의 공개 GitHub 저장소로부터 NVIDIA DLSS SDK(헤더, `nvsdk_ngx_s.lib`, `nvngx_dlss.dll`)를, NuGet에서
ONNX Runtime(DirectML 빌드)과 DirectML을, Hugging Face에서 Depth Anything V2 Small FP16 모델을 내려받습니다
(`-DVDC_FETCH_DEPTH_MODEL=OFF`로 모델을 건너뛸 수 있음). 모든 다운로드는 해시를 검증합니다. 셰이더는 실행 시
컴파일되므로 셰이더 도구 체인이 필요 없습니다. DLSS 5 런타임은 빌드나 패키지에 절대 포함되지 않습니다.

## 동작 원리

<details>
<summary>파이프라인과 설계 노트</summary>

```
VRChat Stream Camera ──Spout──▶ D3D11on12 receive ──▶ convert (sRGB / resize)
      ▶ NVIDIA Optical Flow (forward + backward) / block matching ──▶ motion vectors + confidence
      ▶ Depth Anything V2 (ONNX Runtime DirectML, every N frames) ──▶ normalized depth, reprojected in between
      ▶ [DLAA] ──▶ DLSSNR (nvngx_dlssnr.dll) ──▶ composite / compare ──▶ preview + PNG capture
Video file ──Media Foundation──▶ decode (GPU) ──▶ same pipeline, one frame at a time ──▶ MP4 (H.264 / HEVC + AAC) or PNG sequence
```

이 앱은 NGX 런타임 바깥에서 DLSS 5 뉴럴 렌더링 스니펫을 호스팅합니다. DLL을 직접 로드하고, 모듈 이름 검사를
통과시키며, `DLSSNR.*` NGX 매개변수 규약으로 D3D12 큐에서 기능을 생성하고 평가합니다(`src/ngx/DlssnrFeature.cpp`).
매개변수는 RenoDX DLSS 5 애드온이 제공하는 것과 같은 항목입니다.

가이던스 방식은 동영상 입력에 맞춰 설계되었습니다. 동일 해상도의 SDR 입력, 정방향과 역방향 벡터가 일치하지 않는
곳의 신뢰도를 낮추는 하드웨어 옵티컬 플로우, Depth Anything V2의 단안 깊이를 (2/98 백분위수로) 반전 상대 깊이로
정규화하고 추론 사이에는 모션 벡터를 따라 이동시키는 방식, 그리고 프레임마다 이력을 초기화하지 않는 것입니다.
모두 독립적인 MIT 구현입니다(`src/gfx/Pipeline.cpp`, `src/gfx/DepthEstimator.cpp`, `src/gfx/Shaders.cpp`).
옵티컬 플로우 엔진은 전용 네이티브 D3D11 장치에서 실행되며, 프레임과 벡터는 공유 펜스로 순서가 보장되는 NT 핸들
공유 텍스처를 통해 D3D12로 넘어갑니다(`src/gfx/NvOpticalFlow.cpp`).

두 스레드가 GPU를 공유합니다. 처리 스레드는 Spout 수신기(또는 파일), 파이프라인, 전용 D3D12 큐를 소유하고,
인터페이스 스레드는 창, ImGui, 높은 우선순위의 프레젠트 큐를 소유합니다. 완성된 화면은 큐 간 펜스 대기가 있는
디스플레이 버퍼를 통해 전달되므로, 미리보기는 항상 가장 최근에 완성된 프레임을 보여 주고 창은 뉴럴 패스를
기다리지 않습니다(`src/core/App.cpp`, `src/gfx/Device.cpp`). 정지 이미지는 WIC로 디코딩(EXIF 방향 적용)하여
한 번만 업로드한 뒤, 같은 파이프라인을 모션 0으로 시간적 네트워크가 안정될 때까지 여러 패스 통과시킵니다.

동영상 파일은 Media Foundation 소스 리더가 전용 스레드에서 디코딩(DXGI 장치 관리자를 통한 하드웨어 디코더, 실패 시
소프트웨어)하여 짧은 프레임 대기열에 넣습니다. 처리 스레드는 파이프라인에 한 번에 한 프레임씩 넘기고 그 프레임
결과의 리드백을 요청합니다. 리드백은 프레임 순서대로 모아 라이터에 전달하므로, 뉴럴 패스가 프레임 간격보다 오래
걸려도 프레임이 빠지거나 중복되지 않습니다. 라이터는 전용 스레드에서 각 프레임을 NV12로 변환하여 디코딩된 오디오
샘플과 함께 Media Foundation 싱크 라이터(가능하면 하드웨어 인코더)에 보냅니다(`src/core/VideoSource.cpp`,
`src/core/VideoWriter.cpp`).

</details>
