# VRChat DLSS5 Cam

[English](../README.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · **한국어**

VRChat DLSS5 Cam은 VRChat 카메라의 화면에 GeForce RTX에서 NVIDIA **DLSS 5 뉴럴 렌더링**을 적용하고, 그 결과를
무손실 PNG로 기록하는 Windows 애플리케이션입니다. 디스크에 있는 이미지와 동영상도 동일한 파이프라인을 거치며,
개별 처리와 일괄 처리를 모두 지원합니다. 일반적인 Windows 프로그램이므로 VRChat 프로세스에는 전혀 개입하지 않고
모드도 필요하지 않습니다.

## 주요 기능

- **실시간 카메라.** VRChat의 Stream 카메라를 Spout으로 받아 DLSS 5 적용 결과를 실시간으로 표시합니다.
  전역 단축키(`Ctrl+Alt+P`)는 VRChat이 앞에 있을 때도 동작하며, 그대로 무손실 PNG를 저장합니다.
- **이미지와 동영상 파일.** 스크린샷이나 녹화 파일을 창에 끌어다 놓고 파라미터를 조정한 뒤 내보낼 수 있습니다.
  출력 형식은 이미지가 PNG, 동영상이 MP4(H.264 / HEVC, 오디오 트랙 유지) 또는 PNG 시퀀스입니다.
- **일괄 처리.** 불러온 파일은 미리보기 아래 라이브러리에 모이며, 선택한 항목을 한 번에 처리할 수 있습니다.
  공통 파라미터 외에 파일별 개별 파라미터도 지원하고, 처리 전 회전·반전·잘라내기도 적용할 수 있습니다.
- **진짜 DLSS 5 가이던스.** NVIDIA Optical Flow의 모션 벡터와 Depth Anything V2의 깊이 맵이 네트워크에 전달되므로,
  동영상과 실시간 화면이 게임과 동일한 시간적 단서를 갖고 처리됩니다. 앞단에는 DLAA 패스를 선택적으로 넣어
  가장자리를 먼저 정리할 수도 있습니다.
- **비교와 확인.** 와이프, 나란히 보기, 원본 보기에 더해 휠 확대, 드래그 이동, 전체 화면을 지원하여 처리 전후의
  차이를 1:1로 확인할 수 있습니다.
- **일상적인 사용을 위한 구성.** Windows 설정을 따르는 다크·라이트 테마, 기록이 남는 실행 취소와 다시 실행,
  이름을 지정하는 프리셋, 모든 설정을 대상으로 하는 검색, 크기를 바꿀 수 있는 레이아웃, 업데이트 자동 확인,
  4개 언어(English, 简体中文, 日本語, 한국어) 인터페이스, 전용 스레드로 동작하는 안정적인 인터페이스,
  스크립트 실행용 명령줄을 제공합니다.

## 동작 환경

| | |
|---|---|
| Windows | Windows 10 21H2 또는 Windows 11, 64비트 |
| 그래픽 카드 | NVIDIA GeForce RTX. **RTX 50** 시리즈와 **RTX 40 / 30 / 20** 시리즈에는 각각 맞는 런타임 빌드가 압축 파일에 들어 있어(다음 행 참고) 어느 세대에서도 파일을 따로 준비할 필요가 없습니다. **AMD Radeon RX 7000 / 9000**은 Radeon 에디션(`VRChatDLSS5Cam-win64-amd.zip`)으로 지원합니다. 뉴럴 패스는 별도 프로젝트인 DLSS-NR-on-AMD가 수행하며 앱 안에서 설치할 수 있습니다(*AMD Radeon 카드* 참고). 다른 제조사의 카드도 거부하지 않습니다. 뷰어와 녹화 도구로 동작합니다. DLAA와 하드웨어 옵티컬 플로우는 NVIDIA 전용으로 남으며, 모션은 블록 매칭이 대신합니다. |
| DLSS 5 런타임 | 포함. 압축 파일에는 `nvngx_dlssnr.dll` 310.8.0.0이 두 가지 빌드로 들어 있습니다. `runtimes\blackwell\`은 게임에 실리는 그대로의 빌드(RTX 50), `runtimes\universal\`은 같은 런타임을 커뮤니티가 RTX 40 / 30 / 20용으로 적합화한 빌드입니다. 시작할 때 설치된 카드에 맞는 빌드가 선택되고, 실패하면 다른 빌드를 시도합니다. 두 파일 모두 NVIDIA의 소프트웨어이며 NVIDIA의 약관을 따릅니다. 이 프로젝트의 MIT 라이선스 소스에는 포함되지 않습니다(`THIRD_PARTY_NOTICES.md` 참고). 다른 곳에서 구할 파일은 없습니다. |
| VRChat | Stream 카메라에 *Spout Stream* 옵션이 있는 모든 빌드(데스크톱 또는 VR). 실시간 카메라에만 필요합니다. |
| 동영상 파일 | Windows Media Foundation(Windows에 포함). N / KN 에디션은 *Media Feature Pack*이 필요하며, HEVC 파일은 Microsoft Store의 *HEVC 비디오 확장*이 필요할 수 있습니다. |

## 설치와 실행

| 사용 중인 그래픽 카드 | 내려받을 파일 | 비고 |
|---|---|---|
| NVIDIA GeForce RTX 20 / 30 / 40 / 50 | `VRChatDLSS5Cam-win64.zip` | DLSS 5 런타임이 압축 파일에 들어 있습니다. |
| AMD Radeon RX 7000 / 9000 | `VRChatDLSS5Cam-win64-amd.zip` | Radeon 에디션. 처음 시작할 때 DLSS-NR-on-AMD 설치 프로그램을 대신 내려받습니다. 현재 버전에서 기대할 수 있는 것은 [AMD Radeon 카드](#amd-radeon-카드)를 참고하세요. |

1. [최신 릴리스](https://github.com/AlanBacker/VRChat-DLSS5-Cam/releases/latest)에서 `VRChatDLSS5Cam-win64.zip`을 내려받아 원하는 위치에 압축을 풉니다. (Radeon 카드라면 대신 `VRChatDLSS5Cam-win64-amd.zip`을. 아래 *AMD Radeon 카드* 참고.)
2. 더 복사할 파일은 없습니다. DLSS 5 런타임은 압축 파일의 `runtimes\` 아래에 RTX 50용과 RTX 40 / 30 / 20용 두 가지 빌드로 들어 있습니다. 앱은 시작할 때 설치된 카드에 맞는 빌드를 고르고, 실패하면 다른 빌드로 전환합니다. 사용 중인 빌드는 DLSS 5 섹션의 *런타임* 옆에 표시되고 경로는 `log.txt`에 기록됩니다.

   ```
   VRChatDLSS5Cam.exe
   runtimes\blackwell\nvngx_dlssnr.dll   RTX 50
   runtimes\universal\nvngx_dlssnr.dll   RTX 40 / 30 / 20
   runtimes\other\nvngx_dlssnr.dll       다른 제조사용 런타임(포함되지 않음. Radeon은 Radeon 에디션 사용)
   ```

   대신 자신의 파일을 쓸 수도 있습니다. `VRChatDLSS5Cam.exe` 옆의 `nvngx_dlssnr.dll`은 카드에 맞는 빌드 다음에 시도되며, 어떤 파일이든 *DLSS 5 뉴럴 렌더링 → 런타임 경로*에서 선택할 수 있습니다.
3. VRChat에서 **카메라**를 열고 **Stream** 모드로 전환한 뒤, 카메라 설정에서 **Spout Stream**을 켭니다.
4. `VRChatDLSS5Cam.exe`를 실행합니다. DLSS 5가 적용된 카메라 화면이 미리보기에 나타나고, *DLSS 5(DLSSNR) 사용* 스위치 옆의 배지가 *동작 중*으로 표시됩니다.
5. VRChat에서 구도를 잡고 **Ctrl+Alt+P**(또는 *촬영* 버튼)를 누릅니다. PNG는 `Pictures\VRChat DLSS5 Cam`에 저장됩니다.

실시간 카메라 참고 사항

- 스트림 해상도는 VRChat이 결정합니다. VRChat의 `config.json`에서 `camera_spout_res_width` / `camera_spout_res_height`를 높이면 더 선명한 입력을 얻을 수 있고, 앱은 자동으로 맞춥니다.
- 뉴럴 패스가 실시간 미리보기에 너무 느린 카드에서는 DLSS 5 섹션의 *촬영 시에만 뉴럴 패스 실행*이 유용합니다. 미리보기에는 원본 화면이 표시되고 뉴럴·모션·깊이 패스가 모두 쉬며, 촬영할 때마다 사진을 위해서만 뉴럴 패스가 실행됩니다.
- *표시* 섹션의 *처리 속도 상한*은 초당 처리하는 카메라 프레임 수를 제한하여 GPU를 VRChat에 여유 있게 남겨 둡니다.

## AMD Radeon 카드

Radeon 에디션(`VRChatDLSS5Cam-win64-amd.zip`)은 [DLSS-NR-on-AMD](https://github.com/danielblnc/DLSS-NR-on-AMD)를 통해 Radeon 카드에서 뉴럴 패스를 실행합니다. DLSS-NR-on-AMD는
Daniel Blanco의 별도 프로젝트로, FSR을 쓰는 프로그램에 붙어 DLSS 5 뉴럴 렌더링을 AMD 하드웨어에서 동작시킵니다. 이 앱에는 그 프로젝트의 내용이 전혀
포함되어 있지 않습니다. Radeon 에디션은 그것이 붙을 FSR 컨텍스트(AMD의 FidelityFX API, `amd_fidelityfx_dx12.dll`, MIT)를 호스팅하고,
버튼을 누르면 그 프로젝트 자체의 릴리스 페이지에서 설치 프로그램을 받아 옵니다. 그 프로젝트의
[라이선스](https://github.com/danielblnc/DLSS-NR-on-AMD/blob/master/LICENSE)는 개인·비상업 용도의 사용을 허용하고 재배포와 수정을 금지하므로,
설치 프로그램은 이 앱의 압축 파일에 절대 들어가지 않습니다.

1. [최신 릴리스](https://github.com/AlanBacker/VRChat-DLSS5-Cam/releases/latest)에서 `VRChatDLSS5Cam-win64-amd.zip`을 내려받아 원하는 위치에 압축을 풉니다. 실행 파일 옆에
   `amd_fidelityfx_dx12.dll`과 RTX 50용 빌드의 `nvngx_dlssnr.dll`이 들어 있습니다(2단계의 설치 프로그램이 후자를 자체 가중치로 변환합니다).
   NVIDIA 전용 파일(`nvngx_dlss.dll`, `runtimes\`)은 들어 있지 않습니다. GeForce 에디션은 Radeon 카드에서 실행되면 **Radeon 에디션 받기…**를
   보여 주며(명령줄의 `--edition amd`도 같은 일을 합니다), 업데이트와 같은 방식으로 자신의 파일을 바꿉니다.
2. `VRChatDLSS5Cam.exe`를 실행합니다. 시작 카드와 DLSS 5 섹션에 **DLSS-NR-on-AMD 설치…**가 라이선스 링크와 함께 나타납니다. 한 번 누르면
   `dlssnr_on_amd_setup.exe`를 프로그램 폴더에 내려받아 백그라운드에서 실행하며, 폴더와 실행 파일에 제안되는 DLL 이름을 자동으로 수락하므로 창도
   키 입력도 필요 없습니다. 끝나면 앱이 스스로 다시 시작되고, DLSS 5 섹션에 *런타임: 로드됨 FSR … · FSR 호스트*와
   *DLSS-NR-on-AMD v…: 로드됨(version.dll) · 최신 버전*이 표시되며 *DLSS 5 켜기* 스위치 옆의 배지가 *활성*으로 바뀝니다. 폴더에 관리자 권한이
   필요하거나 포트가 지원하지 않는 카드라면 설치 프로그램이 대신 자체 창을 열어 메시지를 볼 수 있게 합니다.

DLSS 5 섹션은 설치된 릴리스와 최신 릴리스를 나란히 보여 줍니다. DLSS-NR-on-AMD의 새 릴리스가 나오면 섹션이 이를 알리고 버튼이
**…(으)로 업데이트**로 바뀝니다. 이 버튼과 **설치 프로그램 다시 실행…**은 설치 프로그램을 받아 그 창을 열며, 창에서 **U**로 업데이트(설정과 가중치 유지),
**R**로 제거합니다. 이 버전 이전에 한 설치는 실행 파일 옆의 설치 프로그램 파일로 인식됩니다.

이 방식에서는 1까지의 뉴럴 패스 강도가 DLSS-NR-on-AMD의 것이며 자체 오버레이(**End** 키)에서 설정합니다. 오버레이의 *Mode*는 inline으로
둡니다(저장되는 프레임에 필요합니다. 아래 참고). 이 앱의 *프리셋*, *스타일*, 강도 값은 전달되지 않습니다. 패스 뒤에서 작용하는 컨트롤(*출력 블렌드*,
1을 넘는 강도, *뉴럴 패스* 해상도)은 평소처럼 동작합니다. DLSS-NR-on-AMD에는 Windows 11, Radeon RX 7000 또는 RX 9000 카드, Adrenalin 26.1.1 이상이
필요합니다. 최신 요구 사항은 그 릴리스 페이지를 참고하세요. *고급*의 *호스트 방식*에서 방식을 직접 고를 수 있습니다(*자동*은 Radeon에서 FSR 호스트,
GeForce에서 직접 방식을 선택합니다).

Radeon 에디션은 RX 9060 XT에서 실행을 확인했습니다(720p와 4K 정지 화상, 동영상 파일, 명령줄 일괄 처리, 그리고 실시간 VRChat 카메라 화면.
프레임률은 GeForce 카드보다 낮습니다. 아래 목록 참고). DLSS-NR-on-AMD의 설치 프로그램이 기록하는 inline 대기 시간은 게임에 맞춘 200 ms로, 이를 넘긴 프레임은 이전 프레임의 결과를
표시합니다. 앱은 설치 후(시작 시 파일에 아직 낮은 값이 남아 있으면 한 번 자동으로 다시 시작해서) `dlssnr_on_amd.ini`의 `InlineWaitMs`를 1000으로
올려 저장되는 사진이나 동영상 프레임이 그 프레임 자신의 결과를 담도록 하고, `Inline`은 1로 둡니다. 그 파일의 다른 부분은 바꾸지 않습니다.
`log.txt`(`%LOCALAPPDATA%\VRChatDLSS5Cam\`)에는
실행 파일 옆의 DLSS-NR-on-AMD 파일이 기록되고 끝에는 그 프로젝트 자체 로그(프로그램 폴더의 `dlssnr_on_amd.log`)의 마지막 몇 줄이 붙습니다.
이를 첨부한 보고를 이슈에서 기다립니다.

### 현재 버전에서 Radeon에 기대할 수 있는 것

- **카드.** Windows 11의 Radeon RX 7000과 RX 9000(Adrenalin 26.1.1 이상), 즉 DLSS-NR-on-AMD가 지원하는 카드입니다. 작성자의 시험은 RX 9060 XT에서
  했습니다. 더 오래된 Radeon에서는 FSR 호스트는 실행되지만 이 포트의 네트워크는 동작하지 않아 화면이 그대로 돌아옵니다.
- **되는 것.** 정지 화상, 동영상 파일, 일괄 처리 대기열, 촬영과 타임랩스를 포함한 실시간 VRChat 카메라 화면, 깊이 네트워크, 패스 뒤의 컨트롤
  (*출력 블렌드*, 1을 넘는 강도, *뉴럴 패스 해상도*), 업데이트, 에디션 전환.
- **느린 점.** DLSS-NR-on-AMD는 네트워크를 inline으로 실행하고 프레임은 그 완료를 기다립니다. RX 9060 XT에서 720p는 약 25 ms, 4K는 약 180 ms라
  4K 실시간 화면은 초당 몇 프레임이 됩니다. *뉴럴 패스 해상도*의 *최대 해상도* 상한과 *처리 속도 상한*으로 실시간 화면을 부드럽게 유지할 수
  있습니다. 저장되는 사진과 동영상의 결과는 같고 시간만 더 걸립니다.
- **하드웨어 옵티컬 플로우 없음.** 옵티컬 플로우 엔진은 GeForce 드라이버의 것입니다. Radeon에서는 모션 벡터가 GPU 블록 매칭에서 나오며 빠른
  움직임에서는 더 거칩니다. *프레임 가이던스* 아래의 상태 점이 이를 표시합니다.
- **강도와 프리셋.** 이 포트는 *프리셋*, *스타일*, 1까지의 강도를 자체 오버레이(**End** 키)에서 보관합니다(위 참고).
  그래서 여기서 그 슬라이더를 움직이면 기존 결과를 바로 다시 합성할 뿐(1을 넘는 값은 합성에서 반영됩니다) 이미지를 패스에 다시 통과시키지 않습니다.
  Radeon에서는 그 작업이 4K 기준 약 4초가 걸리는데 그림은 달라지지 않기 때문입니다.
- **깊이 네트워크와 포트가 번갈아 GPU를 씁니다.** 포트의 네트워크와 깊이 네트워크(DirectML)는 GPU를 동시에 쓸 수 없습니다. 깊이 네트워크의 워밍업과 겹친
  신경망 패스는 0.17초에서 2.7초로 늘어나 드라이버의 2초 제한을 넘겼고 그래픽 장치가 손실됐습니다(드라이버가 재시작되고 프로그램을 다시 열어야 합니다).
  v1.5.0부터는 신경망 패스마다 그 전에 깊이 네트워크가 끝나기를 기다리므로 둘이 겹치지 않습니다. 이미지의 첫 패스들은 깊이 네트워크가 준비된 뒤 시작합니다.
  앞서 4K 일괄 처리에서 본 한 프레임 3초 멈춤(포트 로그의 watchdog spike)도 같은 겹침이었습니다.
- **유휴 부하.** 이미지가 패스를 마치면 GPU는 유휴 상태가 됩니다(RX 9060 XT에서 약 2 %, GeForce와 같음). 다만 첫 신경망 패스부터 프로그램을 닫을 때까지
  CPU 코어 하나가 계속 바쁩니다. DLSS-NR-on-AMD의 스레드가 GPU를 전속력으로 폴링하기 때문입니다(inline 모드). 이 스레드는 포트의 것이며 FSR 컨텍스트를 해제해도 멈추지 않습니다.

**예정:** 이 앱 자체의 옵티컬 플로우 패스. AMD FidelityFX SDK의 옵티컬 플로우(MIT)를 이식해 Radeon에서는 블록 매칭을 대체하고 GeForce에서는
두 번째 소스로 씁니다.

## 이미지와 동영상 파일

파일은 창에 끌어다 놓거나 *소스* 섹션의 *이미지 열기…* / *동영상 열기…*로 불러올 수 있습니다. 화면이 미리보기에
나타나고 모든 슬라이더가 바로 적용됩니다. *열기…* 옆의 ✕ 버튼은 파일을 다시 닫으며, 처리가 멈추고 미리보기가
비워지고 파일은 라이브러리에 남습니다. **처리 후 PNG 저장**(이미지), **처리 후 동영상 저장**(동영상) 또는 단축키를
누르면 결과가 원본 파일과 같은 위치에 `<name>_DLSS5_<w>x<h>.png`, `.mp4` 또는 PNG 프레임이 담긴 폴더로 기록됩니다.

동영상의 경우 미리보기 아래의 컨트롤로 파일을 전체 파이프라인을 거쳐 재생·일시정지하고, 한 프레임씩 이동하며,
탐색 바 위의 커서 위치에 있는 프레임을 작은 그림으로 보여 줍니다. *여기를 시작점으로* / *여기를 끝점으로*는
처리(그리고 오디오)를 한 구간으로 제한하고, *전체 동영상*은 그 제한을 해제합니다. 기본적으로 출력은 원본을 따라
같은 코덱, 프레임 속도, 비트레이트를 사용합니다. *원본 영상 규격에 맞추기*를 끄면 H.264, HEVC 또는 PNG 시퀀스와
비트레이트를 개별적으로 고를 수 있습니다. *촬영* 섹션은 현재 설정으로 파일 처리에 대략 얼마나 걸릴지 보여 줍니다.

## 일괄 처리

열거나 끌어다 놓은 모든 파일은 미리보기 아래의 **라이브러리**에 모입니다(*파일 추가…*와 *폴더 추가…*로 더 추가할
수 있습니다). 썸네일을 **더블클릭**하면 그 파일이 미리보기에 열려 슬라이더를 조정할 수 있습니다. 한 번 클릭하면
그 파일만 선택되고, **Ctrl+클릭**은 하나를 추가하거나 해제하며, **Shift+클릭**은 마지막으로 클릭한 파일부터
범위를 넓힙니다. 빈 공간에서 드래그하면 사각형 선택이 되고, 빈 공간을 클릭하면 선택이 모두 해제되며, 각 썸네일의
체크박스로도 켜고 끌 수 있고, **Ctrl+A**는 읽을 수 있는 파일을 모두 선택합니다. 마우스가 라이브러리 위에 있을 때
(또는 마지막 클릭이 라이브러리 안에서 이루어졌을 때) **Delete** 키는 선택한 항목을 라이브러리에서 빼며, 디스크의
파일은 그대로 남습니다. 이어서 *선택 항목 처리* 또는 *모두 처리*를 누르면 파일이 차례로 처리되고, 각 썸네일의 막대가
진행률을 보여 주며 처리 후에도 상태가 남아 있습니다.

썸네일에서 마우스 오른쪽 버튼을 누르면 메뉴가 열립니다: 탐색기에서 파일 표시, 라이브러리에서 제거, 또는 별도 창에서
**그 파일만의 DLSS 5 매개변수** 설정. 여러 파일을 선택한 상태에서는 같은 메뉴에 *N개 파일의 개별 매개변수…*가
나타나 모든 파일의 값을 한 번에 설정하며, 이후 각 파일이 자신의 값을 유지합니다.

라이브러리의 파일을 미리보기에 열면 화면 위에 작은 도구 모음이 나타나 **회전, 반전, 자르기**를 할 수 있습니다.
왼쪽이나 오른쪽으로 90도 회전, 수평 또는 수직 반전, 또는 자르기 틀을 꺼내 모서리와 변을 드래그(틀 안을 드래그하면
이동)한 뒤 **Enter**나 *적용*으로 확정하고 **Esc**로 취소합니다. 마지막 버튼은 파일을 원래대로 되돌립니다.
파일마다 방향과 자르기를 따로 기억하고, 처리와 저장 결과에는 회전·자르기 후의 화면이 쓰이며, 각 단계는 히스토리에
기록되어 실행 취소할 수 있습니다. 라이브 화면에도 자르기를 뺀 같은 도구 모음이 있어, VRChat 카메라 화면의 회전이나
반전은 미리보기·촬영·타임랩스에 모두 적용되고 다음 실행 때도 유지됩니다. 도구 모음 자체도 옮길 수 있습니다. 왼쪽 끝의 손잡이를 드래그해
움직이고, 화면 가장자리 밖에 놓거나 오른쪽 끝의 화살표를 누르면 그 가장자리에 접혀 들어가며, 가장자리에 남는 작은 탭으로 다시 펼칩니다.
위치도 다음 실행 때 유지됩니다.

## 인터페이스 사용법

- **일상적인 작업은 세 섹션이 담당합니다:** *소스*(무엇이 들어오는지), *DLSS 5 뉴럴 렌더링*(어떻게 보이는지),
  *촬영*(어디로 가는지). 그 뒤로 *표시*와 *정보*가 이어집니다. DLSS 5 섹션의 *고급* 스위치는 톤·구조 슬라이더,
  출력 블렌드, *촬영* 다음에 들어가는 *프레임 가이던스*와 *DLAA 프리패스* 섹션, 그리고 *정보* 앞에 들어가는
  타이머가 있는 *내부 정보*를 표시하거나 숨깁니다.
- **비교**는 와이프(미리보기의 핸들을 드래그), 나란히 보기, 원본으로 할 수 있습니다. 와이프는 인터페이스 자체의
  프레임 속도로 마우스를 따라가므로 동영상이 느리게 재생될 때도 끊기지 않습니다. 미리보기 위의 마우스 휠은 커서를
  중심으로 확대·축소하고, 드래그하면 이동하며, 더블클릭하면 창 맞춤 보기로 돌아갑니다.
- **프리셋**은 DLSS 5 섹션에서 만듭니다. *+*는 현재 값을 이름을 붙여 저장하고, 목록을 클릭하면 적용되며, 각 항목은
  현재 값으로 덮어쓰거나 이름을 바꾸거나 삭제할 수 있습니다. 설정 폴더의 `presets.txt`에 저장됩니다.
- **검색**은 사이드바 맨 위의 검색창에서 이루어지며, 일치하는 컨트롤과 그 섹션만 남습니다. **Esc**나 ✕로 지웁니다.
- **실행 취소와 다시 실행**은 설정의 모든 변경과 라이브러리에 파일을 추가하거나 제거한 것을 대상으로 하며,
  **Ctrl+Z** / **Ctrl+Y** 또는 상단 바의 두 화살표로 조작합니다. 화살표 옆의 시계 버튼을 누르면 **히스토리**가 열려
  기록된 모든 변경이 목록으로 나타납니다(*강도: 1.2*, *photo.png 추가*, *파일 3개 제거*, *photo.png: 개별 값*).
  현재 상태는 강조되고, 실행 취소한 상태는 그 아래에 흐리게 표시됩니다. 항목을 클릭하면 그 상태로 이동하며,
  새 변경을 하기 전까지 뒤쪽 항목이 그대로 남아 있어 자유롭게 오갈 수 있습니다. 최대 100단계까지 보관됩니다.
- **전체 화면**은 미리보기 모서리의 버튼이나 **F11**로 들어가며, 화면 전체에 영상만 표시됩니다. 마우스를 움직이면
  동영상 컨트롤이 나타나고 **Esc** 또는 **F11**로 나갑니다. 들어가고 나갈 때 페이드되며, *실시간*·*이미지*·*동영상*
  사이의 전환도 마찬가지로 페이드됩니다.
- **다크 또는 라이트.** *표시* 섹션의 *테마*: *시스템*은 Windows의 앱 색상 설정을 따르며, *다크*나 *라이트*를
  직접 고를 수도 있습니다.
- **사이드바**는 가장자리의 길쭉한 막대 뒤로 밀려 숨겨지고, 라이브러리 위에도 같은 모양의 막대가 있습니다.
  **막대를 클릭**하면 패널이 접히거나 펼쳐집니다. 드래그 대상은 **막대 안쪽 가장자리의 가느다란 선**으로, 마우스를
  올리면 파랗게 빛나고 커서가 크기 조절 화살표로 바뀝니다. 이 선을 **드래그**하면 사이드바 너비나 라이브러리 높이가
  바뀌고 썸네일도 함께 커지거나 작아집니다. 두 크기 모두 다음 실행까지 기억됩니다. 파일을 처리하는 동안에는 잠기며
  *취소*를 제공합니다.
- **도움말**은 한 번의 클릭으로 열립니다. 상단 바의 *?* 버튼(또는 *정보*의 *문서*)이 인터페이스 언어로 이 안내서를
  엽니다.
- **시작할 때**는 아이콘, 이름, 버전(프리릴리스 빌드에는 *Pre-release* 표시), 상태 한 줄, 움직이는 막대가 있는 작은
  카드가 나타나고, 메인 창은 첫 프레임이 준비된 뒤에야 페이드인됩니다. 그래서 시작할 때 빈 창이 보이지 않습니다.
  지난 세션의 파일은 *표시* 섹션의 *시작할 때 마지막 파일 다시 열기*(기본 꺼짐)가 켜져 있을 때만 다시 열립니다.

전에 테스트용으로 공개된 빌드까지. 정식 릴리스도 이 채널로 오며, 업데이트 창은 각 릴리스가 *정식 릴리스*인지 *프리릴리스*인지 표시합니다). *시작 시 업데이트 확인*으로 이 확인을 끌 수 있고, *업데이트 확인* 버튼으로는
언제든 직접 실행할 수 있으며, 마지막 확인 결과가 그 아래에 표시됩니다.

새 버전이 있으면 버전, 게시 날짜, 릴리스 노트와 버튼 세 개가 있는 창이 열립니다. **지금 업데이트**는 릴리스 zip을
`%LOCALAPPDATA%\VRChatDLSS5Cam\update`에 내려받아 압축을 풀고, 앱을 닫은 뒤 프로그램 파일을 바꾸고 다시
시작합니다. 설정과 라이브러리는 건드리지 않고, `runtimes\` 아래의 내장 런타임은 릴리스의 것으로 바뀌며, 실행 파일
옆에 둔 자신의 런타임 파일은 그대로 남습니다.
**릴리스 페이지**는 브라우저에서 해당 릴리스를 열고, **나중에**는 창을 닫습니다. 프로그램 폴더는 쓰기가 가능해야
하는데 `Program Files` 아래 폴더는 보통 그렇지 않습니다. 그럴 때는 앱이 그렇게 알려 주므로 릴리스 페이지에서
직접 업데이트하면 됩니다. 확인이나 업데이트가 실패하면 알림으로 표시됩니다.

이 `api.github.com` 요청(그리고 업데이트를 선택했을 때 `github.com`에서 내려받는 것)은 앱이 하는 유일한 네트워크
접속이며, 그 밖에는 아무것도 보내지 않습니다. 창 없는 실행과 `--process` 실행에서는 자동으로 확인하지 않습니다.

## 문제 해결

- **"VRChat Spout 스트림 대기 중…"** – VRChat의 Stream 카메라에서 *Spout Stream*이 켜져 있어야 하고, 카메라도 열려 있어야 합니다. 다른 Spout 송신자는 *Spout 송신자* 상자에 표시됩니다.
- **"런타임 파일이 없습니다"** – 압축 파일이 완전히 풀리지 않았습니다. `runtimes\blackwell\nvngx_dlssnr.dll`과 `runtimes\universal\nvngx_dlssnr.dll`은 `VRChatDLSS5Cam.exe` 옆에 있어야 합니다. 다시 풀거나 *런타임 경로*에서 런타임 파일을 선택하면 됩니다.
- **뉴럴 렌더링 실패** – 앱이 스스로 다른 내장 빌드로 전환하고 알림으로 알려 줍니다. 두 빌드 모두 시작되지 않으면 오류 아래에 그렇게 표시됩니다. 먼저 더 새로운 그래픽 드라이버를 시도해 볼 만하고, `log.txt`에 NGX 결과 코드가 남으며, *프리셋* 0과 *NGX 코어* 방식도 시도해 볼 수 있습니다. Radeon 카드에서는 뉴럴 패스가 Radeon 에디션과 DLSS-NR-on-AMD로 동작합니다(*AMD Radeon 카드* 참고).
- **FSR 호스트는 동작하는데 화면이 그대로임** – DLSS-NR-on-AMD가 이 프로세스에 붙어 있지 않습니다. DLSS 5 섹션에 *DLSS-NR-on-AMD: 로드되지 않음*이 표시됩니다. 거기서 설치하세요(**DLSS-NR-on-AMD 설치…**). 설치 프로그램이 끝나면 앱이 스스로 다시 시작됩니다. 설치되어 있는데 로드되지 않으면 설치 프로그램을 다시 실행하세요. 로드되었는데도 변화가 없다면 오버레이(**End** 키)를 열어 켜져 있는지 확인하고 다른 *Mode*를 시도해 보세요. 자체 로그(프로그램 폴더의 `dlssnr_on_amd.log`, 마지막 몇 줄은 `log.txt` 끝에도 붙습니다)에 무엇을 했는지 적혀 있습니다. 이 포트는 자체 요구 사항을 가진 별도 프로젝트입니다.
- **amd_fidelityfx_dx12.dll이 없음** – FSR 호스트 방식에는 실행 파일 옆에 그 파일이 필요합니다. Radeon 에디션(`VRChatDLSS5Cam-win64-amd.zip`)에 들어 있습니다.
- **뉴럴 패스는 동작 중인데 화면이 검거나 변화가 없음** – 앱은 모든 뉴럴 프레임을 입력과 비교하며, 런타임이 성공을 보고하면서 검은 화면이나 변화 없는 화면을 내놓으면 경고합니다(`log.txt`: "DLSSNR output check"). DLSS 5를 껐다가 다시 켜면 새로 시작합니다. 그래도 계속되면 그 런타임 빌드는 이 GPU에서 화면을 만들지 못하는 것입니다. (*강도*가 0이면 화면에 변화가 없는 것이 정상이며 경고도 표시되지 않습니다.)
- **앱이 시작되지 않음 / 바로 종료됨** – `%LOCALAPPDATA%\VRChatDLSS5Cam\`에 `log.txt`(마지막 줄이 실패한 단계)와 `crash.txt`가 있습니다. 이슈에는 두 파일을 함께 첨부하면 됩니다.
- **NGX 초기화 안 됨 / DLAA 지원 안 됨** – NGX 런타임에는 NVIDIA GPU와 최신 드라이버가 필요합니다. DLSS 5는 *직접(signed snippet)* 방식으로 계속 동작합니다.
- **깊이 추정기 사용 불가** – `onnxruntime.dll`, `onnxruntime_providers_shared.dll`, `DirectML.dll`, `models\depth_anything_v2_small_fp16.onnx`가 실행 파일 옆에 있어야 합니다(모두 릴리스 패키지에 포함). 추정기가 준비될 때까지는 0 깊이가 사용되며, 상태는 *프레임 가이던스* 아래에 표시됩니다.
- **옵티컬 플로우 사용 불가** – Radeon 카드에서는 예상된 동작입니다. 옵티컬 플로우 엔진은 GeForce 드라이버의 일부이고 Radeon에는 대응하는 엔진이 없어 블록 매칭이 사용되며, *프레임 가이던스* 아래의 상태 점이 이를 표시합니다. GeForce 카드에서 `log.txt`에 "NVOF unavailable, falling back to block matching"이 보이면 GeForce 드라이버 업데이트가 필요합니다. 그때까지는 블록 매칭이 사용됩니다.
- **동영상 미리보기가 검게 보임** – 많은 영상이 검은 화면에서 페이드인으로 시작합니다. 미리보기는 그런 프레임을 건너뛰고, 표시 중인 프레임이 여전히 어두우면 화면 아래에 알려 줍니다. 탐색 바나 화살표 키로 앞으로 이동하면 해결됩니다.
- **동영상 파일이 열리지 않음 / 인코더 없음** – 지원 형식은 Windows에 설치된 코덱에 따라 다릅니다. HEVC 파일에는 *HEVC 비디오 확장*(Microsoft Store)이, Windows N / KN에는 *Media Feature Pack*이 필요합니다. H.264 인코더가 없으면 출력으로 *PNG 시퀀스*를 고를 수 있습니다. GPU 디코더가 거부하는 파일은 *하드웨어 디코딩*을 끄면 도움이 됩니다.
- **낮은 프레임률** – DLAA를 끄거나, 깊이 갱신 간격을 늘리거나 깊이 네트워크 해상도를 낮추거나, 뉴럴 패스 해상도를 낮추거나, 처리 속도 상한을 설정합니다. 옵티컬 플로우 그리드는 4 px로 두는 편이 좋습니다(2 px와 1 px는 4K에서 훨씬 무겁습니다). 로그에는 15초마다 각 단계의 비용이 담긴 `Perf:` 줄이 기록됩니다.
- **그래픽 장치가 손실됨** – 그래픽 드라이버가 GPU를 재설정했습니다. Windows는 GPU 작업 하나에 약 2초만 허용하는데, 오랫동안 완전히 부하가 걸린 GPU는 이를 넘길 수 있습니다. 전형적인 경우는 실시간 스트림에서 VRChat이 같은 GPU로 렌더링하는 동시에 뉴럴 패스가 매 프레임을 업스케일할 때입니다(`log.txt`: "Device removed", `DXGI_ERROR_DEVICE_HUNG`). 그 순간 GPU를 쓰는 모든 프로그램이 화면을 잃습니다. v1.5.1부터는 드라이버가 돌아오면 앱이 스스로 다시 시작해 알림을 띄우고, 손실된 세션의 로그를 `log.txt` 옆에 `log-device-loss.txt`로 남깁니다. 그 마지막 `Perf:` 줄에 당시의 부하와 VRAM 사용량이 있습니다. 반복되면 부하를 줄이세요: 처리 속도 상한 설정, *뉴럴 패스 해상도* 낮추기 또는 최대 해상도 제한, 출력 해상도 낮추기(초해상도 끄기), 또는 VRChat의 프레임률 제한. 새 그래픽 드라이버도 시도해 볼 만합니다. 스크립트 실행(`--process`, `--headless`, `--exit-after`)에서는 대신 종료 코드 2로 끝납니다.
- **내보낸 동영상에 소리가 없음** – 오디오 트랙이 여러 개인 파일(iPhone의 MOV에는 스테레오 AAC 트랙과 Windows가 디코딩하지 못하는 공간 음향 트랙이 있고, 후자가 먼저 나열됩니다)은 예전에는 첫 트랙만 썼습니다. v1.5.1부터는 디코딩되는 첫 트랙을 쓰며, `log.txt`에 각 트랙과 채택한 트랙이 기록됩니다.
- **업데이트를 설치할 수 없음** – 프로그램 폴더는 쓰기가 가능해야 하는데 `Program Files` 아래 폴더는 보통 그렇지 않습니다. 앱을 사용자 폴더로 옮기거나, 릴리스 페이지에서 새 버전을 내려받아 파일을 직접 바꾸면 됩니다. 설정과 라이브러리는 그대로 유지됩니다.

## 작품 공유

이 애플리케이션으로 완성한 사진과 동영상은 해시태그 **#VRCDLSS5CAM**과 함께 X에 올려 주시면 감사하겠습니다.
같은 태그에서 다른 작례도 확인할 수 있습니다. 버그 제보와 기능 제안은
[GitHub Issues](https://github.com/AlanBacker/VRChat-DLSS5-Cam/issues)에서 받고 있습니다.

## 소스에서 빌드

필요 사항: Visual Studio 2022(MSVC v143, Windows 10 SDK) 및 CMake 3.21 이상.

```powershell
git clone https://github.com/AlanBacker/VRChat-DLSS5-Cam.git
cd VRChat-DLSS5-Cam
cmake -S . -B build -A x64
cmake --build build --config Release --parallel
```

구성 단계에서 NVIDIA의 공개 GitHub 저장소로부터 NVIDIA DLSS SDK(헤더, `nvsdk_ngx_s.lib`, `nvngx_dlss.dll`)를, NuGet에서
ONNX Runtime(DirectML 빌드)과 DirectML을, Hugging Face에서 Depth Anything V2 Small FP16 모델을 내려받습니다
(`-DVDC_FETCH_DEPTH_MODEL=OFF`로 모델을 건너뛸 수 있음). 모든 다운로드는 해시를 검증합니다. 셰이더는 실행 시
컴파일되므로 셰이더 도구 체인이 필요 없습니다. FidelityFX SDK v1.1.4의 헤더와 서명된 `amd_fidelityfx_dx12.dll`(MIT)도 같은 방식으로
AMD의 GitHub 저장소에서 내려받습니다. `-DAPP_EDITION_AMD=ON`은 Radeon 에디션(FSR 호스트 방식, 패키지에 NVIDIA 전용 파일 없음)을
빌드하며 기본값은 GeForce 에디션입니다. DLSS 5 런타임은 빌드의 일부가 아니며, 릴리스 워크플로가 `runtime-310.8` 릴리스에서 두 빌드를
압축 파일에 넣습니다.

## 아키텍처

<details>
<summary>파이프라인과 설계 노트</summary>

```
VRChat Stream Camera ──Spout──▶ D3D11on12 receive ──▶ convert (sRGB / resize)
      ▶ NVIDIA Optical Flow (forward + backward) / block matching ──▶ motion vectors + confidence
      ▶ Depth Anything V2 (ONNX Runtime DirectML, every N frames) ──▶ normalized depth, reprojected in between
      ▶ [DLSS SR / DLAA] ──▶ DLSSNR (nvngx_dlssnr.dll) ──▶ composite / compare ──▶ preview + PNG capture
Video file ──Media Foundation──▶ decode (GPU) ──▶ same pipeline, one frame at a time ──▶ MP4 (H.264 / HEVC + AAC) or PNG sequence
```

이 앱은 NGX 런타임 바깥에서 DLSS 5 뉴럴 렌더링 스니펫을 호스팅합니다. DLL을 직접 로드하고, 모듈 이름 검사를
통과시키며, `DLSSNR.*` NGX 매개변수 규약으로 D3D12 큐에서 기능을 생성하고 평가합니다(`src/ngx/DlssnrFeature.cpp`).
매개변수는 RenoDX DLSS 5 애드온이 제공하는 것과 같은 항목입니다.

가이던스 방식은 동영상 입력에 맞춰 설계되었습니다. 동일 해상도의 SDR 입력, 정방향과 역방향 벡터가 일치하지 않는
곳의 신뢰도를 낮추는 하드웨어 옵티컬 플로우, Depth Anything V2의 단안 깊이를 (2/98 백분위수로) 반전 상대 깊이로
정규화하고 추론 사이에는 모션 벡터를 따라 이동시키는 방식, 그리고 프레임마다 이력을 초기화하지 않는 것입니다.
모두 독립적인 MIT 구현입니다(`src/gfx/Pipeline.cpp`, `src/gfx/DepthEstimator.cpp`, `src/gfx/Shaders.cpp`).
옵티컬 플로우 엔진은 전용 네이티브 D3D11 장치에서 실행되며, 프레임과 벡터는 공유 펜스로 순서가 보장되는 NT 핸들
공유 텍스처를 통해 D3D12로 넘어갑니다(`src/gfx/NvOpticalFlow.cpp`).

Radeon 카드에서는 FSR 호스트 방식(`src/gfx/FsrHost.cpp`)이 DLSS 5 기능의 자리를 대신합니다. FidelityFX API의 FSR 3.1 업스케일링
컨텍스트가 같은 색·깊이·모션 입력으로 원본 크기에서 실행되고, 별도 프로그램인 DLSS-NR-on-AMD가 바깥에서 그 컨텍스트에 붙어 출력에
뉴럴 패스를 적용합니다.

두 스레드가 GPU를 공유합니다. 처리 스레드는 Spout 수신기(또는 파일), 파이프라인, 전용 D3D12 큐를 소유하고,
인터페이스 스레드는 창, ImGui, 높은 우선순위의 프레젠트 큐를 소유합니다. 완성된 화면은 큐 간 펜스 대기가 있는
디스플레이 버퍼를 통해 전달되므로, 미리보기는 항상 가장 최근에 완성된 프레임을 보여 주고 창은 뉴럴 패스를
기다리지 않습니다(`src/core/App.cpp`, `src/gfx/Device.cpp`). 정지 이미지는 WIC로 디코딩(EXIF 방향 적용)하여
한 번만 업로드한 뒤, 같은 파이프라인을 모션 0으로 시간적 네트워크가 안정될 때까지 여러 패스 통과시킵니다.

동영상 파일은 Media Foundation 소스 리더가 전용 스레드에서 디코딩(DXGI 장치 관리자를 통한 하드웨어 디코더, 실패 시
소프트웨어)하여 짧은 프레임 대기열에 넣습니다. 처리 스레드는 파이프라인에 한 번에 한 프레임씩 넘기고 그 프레임
결과의 리드백을 요청합니다. 리드백은 프레임 순서대로 모아 라이터에 전달하므로, 뉴럴 패스가 프레임 간격보다 오래
걸려도 프레임이 빠지거나 중복되지 않습니다. 라이터는 전용 스레드에서 각 프레임을 NV12로 변환하여 디코딩된 오디오
샘플과 함께 Media Foundation 싱크 라이터(가능하면 하드웨어 인코더)에 보냅니다(`src/core/VideoSource.cpp`,
`src/core/VideoWriter.cpp`).

</details>
