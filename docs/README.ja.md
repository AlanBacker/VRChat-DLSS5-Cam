# VRChat DLSS5 Cam

[English](../README.md) · [简体中文](README.zh-CN.md) · **日本語** · [한국어](README.ko.md)

VRChat DLSS5 Cam は、VRChat のカメラの映像を取り込み、お使いの GeForce RTX カードで **DLSS 5 ニューラルレンダリング** を適用し、
その結果をロスレス PNG 写真として保存します。ディスク上の画像や動画に対しても同じ処理を、1 つずつでも、まとめてでも行えます。
通常の Windows プログラムであり、VRChat には何も注入せず、Mod も不要です。

## できること

- **ライブカメラ。** DLSS 5 を適用した VRChat の Stream カメラをリアルタイムで表示し、VRChat が前面にあるときでも効くホットキー
  （`Ctrl+Alt+P`）で PNG 写真を保存します。
- **ディスク上の画像と動画。** スクリーンショットや録画をウィンドウにドロップし、それに対してスライダーを調整して結果を保存します。
  画像は PNG、動画は MP4（H.264 / HEVC、音声を保持）または PNG 連番です。
- **複数のファイルをまとめて。** 開いたファイルはすべてプレビュー下のライブラリに並びます。一部または全部を選択して一括で処理でき、
  各ファイルは共通の設定でも、そのファイル専用の設定でも処理できます。
- **本物の DLSS 5 ガイダンス。** ニューラルネットワークには NVIDIA Optical Flow のモーションベクトルと Depth Anything V2 の
  深度マップが渡されるため、動画とライブカメラはゲームと同じように処理されます。任意の DLAA パスで先にエッジを整えることもできます。
- **比較が簡単。** ワイプ、左右並べて表示、またはオリジナル表示。マウスホイールでズーム、ドラッグで移動。
- **日常使いのために。** ダークとライトの外観（既定では Windows に従います）、すべての変更を一覧にするヒストリー付きの
  元に戻す / やり直し、大きさを変えられるレイアウト、新しいバージョンの自動確認、4 言語（English、简体中文、日本語、
  한국어）、専用スレッドで動く滑らかなインターフェース、スクリプト実行向けのコマンドライン。

| | |
|---|---|
| Windows | Windows 10 21H2 または Windows 11、64 ビット |
| グラフィックカード | NVIDIA GeForce RTX。**RTX 50** シリーズは通常のランタイムでニューラルパスを実行できます。**RTX 40 / 30 / 20** には改変版のランタイムビルドが必要です（次の行を参照）。通常のビルドではアプリが失敗を報告し、ニューラルパスなしで動作を続けます。 |
| DLSS 5 ランタイム | ご自身で用意した `nvngx_dlssnr.dll`。**本プロジェクトには含まれておらず、本プロジェクトがダウンロードすることもありません。** ファイルは [RenoDX の Discord サーバー](https://discord.com/invite/renodx) で共有されており、RTX 50 シリーズ以外のカード向けの改変ビルドもそこで入手できます。そのサーバーは RenoDX プロジェクトのものであり、本プロジェクトの Discord **ではありません**。本プロジェクトには独自の Discord サーバーはありません。 |
| VRChat | Stream カメラに *Spout Stream* オプションがあるビルド（デスクトップまたは VR）。ライブカメラにのみ必要です。 |
| 動画ファイル | Windows Media Foundation（Windows の一部）。N / KN エディションには *Media Feature Pack* が必要です。HEVC ファイルには Microsoft Store の *HEVC ビデオ拡張機能* が必要な場合があります。 |

## クイックスタート

1. [最新リリース](https://github.com/AlanBacker/VRChat-DLSS5-Cam/releases/latest) から `VRChatDLSS5Cam-win64.zip` をダウンロードし、任意の場所に展開します。
2. お持ちの `nvngx_dlssnr.dll` をそのフォルダの `VRChatDLSS5Cam.exe` と同じ場所にコピーします。（後から *DLSS 5 ニューラルレンダリング → ランタイムのパス* でアプリにファイルの場所を指定することもできます。）
3. VRChat で**カメラ**を開き、**Stream** モードに切り替えて、その設定で **Spout Stream** を有効にします。
4. `VRChatDLSS5Cam.exe` を起動します。DLSS 5 を適用したカメラ映像がプレビューに表示され、*DLSS 5（DLSSNR）を有効化* スイッチの隣のバッジが *動作中* になります。
5. VRChat で構図を決めて **Ctrl+Alt+P**（または *撮影* ボタン）を押します。PNG は `Pictures\VRChat DLSS5 Cam` に保存されます。

ライブカメラのヒント

- ストリームの解像度は VRChat が決めます。VRChat の `config.json` で `camera_spout_res_width` / `camera_spout_res_height` を上げるとより鮮明な入力が得られ、アプリは自動的に追従します。
- お使いのカードではニューラルパスが重すぎてライブプレビューに向かない場合は、DLSS 5 セクションの *撮影時のみニューラルパスを実行* をオンにします。プレビューには元の映像が表示され、ニューラル・モーション・深度のパスはすべて休止し、撮影のたびに写真のためだけにニューラルパスが実行されます。
- *表示* セクションの *処理レート上限* は、毎秒処理するカメラフレームの数を制限し、GPU を VRChat のために空けておきます。

## ディスク上の画像と動画

画像や動画をウィンドウにドロップするか、*ソース* セクションの *画像を開く…* / *動画を開く…* を使います。
画像がプレビューに表示され、すべてのスライダーがすぐにそれに効きます。*開く…* の横の ✕ ボタンでファイルを閉じられます:
処理が止まり、プレビューが空になり、ファイルはライブラリに残ります。**処理して PNG を保存**（画像）または
**処理して動画を保存**（動画）、あるいはホットキーを押すと、結果が写真と同じ場所に
`<name>_DLSS5_<w>x<h>.png`、`.mp4`、または PNG フレームのフォルダとして書き出されます。

  <img src="images/video.png" width="900" alt="プレビューで開いた動画。ワイプ比較と、画像の下の再生・コマ送り・範囲のコントロール">
</p>

動画の場合、プレビュー下のコントロールでファイルをパイプライン全体を通して再生・一時停止し、1 フレームずつコマ送りし、
シークバー上のカーソル位置のフレームを小さな画像で表示します。*ここを開始点に* / *ここを終了点に* で処理（と音声）を
範囲に限定し、*動画全体* で解除します。既定では出力は元動画に合わせられ、コーデック、フレームレート、ビットレートが同じになります。
*元動画の仕様に合わせる* をオフにすると、H.264、HEVC、PNG 連番とビットレートを自分で選べます。*撮影* セクションには、
現在の設定でそのファイルにかかるおおよその時間が表示されます。

## 複数のファイルをまとめて処理

開いたりドロップしたりしたファイルはすべて、プレビュー下の **ライブラリ** に並びます（*ファイルを追加…* と *フォルダーを追加…* でさらに追加できます）。
サムネイルを **ダブルクリック** するとそのファイルがプレビューで開き、スライダーを調整できます。シングルクリックは
そのファイルだけを選択し、**Ctrl+クリック** で 1 つ追加または解除、**Shift+クリック** で最後にクリックしたファイルからの
範囲選択、何もない場所をドラッグすると矩形選択になります。各サムネイルのチェックボックスでも切り替えられ、
**Ctrl+A** で読み込めるファイルをすべて選択します。マウスがライブラリの上にあるとき（または最後のクリックが
ライブラリ内だったとき）に **Delete** キーを押すと、選択した項目がライブラリから外れます。ディスク上のファイルは
削除されません。*選択項目を処理* または *すべて処理* でファイルが順番に処理され、各サムネイル上のバーが進捗を示し、
処理後も状態が表示されたままになります。

サムネイルを右クリックするとメニューが開き、エクスプローラーでファイルを表示、ライブラリから外す、または別ウィンドウで
**そのファイル専用の DLSS 5 パラメーター** を設定できます。複数のファイルを選択した状態では、同じメニューに
*N 件のファイルに個別パラメーター…* が現れ、すべてのファイルに一度に値を設定します。その後は各ファイルが自分の値を保持します。

## 画面の見方

- **日常的な作業は 3 つのセクションで行います。** *ソース*（何を入力するか）、*DLSS 5 ニューラルレンダリング*（どう仕上げるか）、
  *撮影*（どこに保存するか）で、その後に *表示* と *情報* が続きます。DLSS 5 セクションの *詳細* スイッチで、トーンと
  構造のスライダー、出力ブレンド、*撮影* の後に入る *フレームガイダンス* と *DLAA プリパス*、そして *情報* の前に入る
  タイマー付きの *内部情報* の表示 / 非表示を切り替えます。
- **比較** はワイプ（プレビュー内のハンドルをドラッグ）、左右並べて表示、またはオリジナルで行います。プレビュー上でマウスホイールを
  回すとカーソル位置を中心にズーム、ドラッグで移動、ダブルクリックでウィンドウに合わせた表示に戻ります。
- **元に戻す・やり直し。** 設定のすべての変更と、ライブラリへのファイルの追加・削除を **Ctrl+Z** / **Ctrl+Y** またはトップバーの 2 つの矢印で元に戻したりやり直したりできます。
  2 つの矢印の隣にある時計ボタンで **ヒストリー** が開き、記録されたすべての変更が一覧になります（*強度: 1.2*、*photo.png を追加*、
  *3 個のファイルを外した*、*photo.png: 個別の値*）。現在の状態が強調表示され、元に戻した状態はその後ろに淡色で並びます。
  どの項目をクリックしてもその状態に戻り、新しい変更を加えるまで後ろの項目は残るので、自由に行き来できます。
  最大 100 ステップまで保持されます。
- **全画面表示** はプレビューの隅のボタンまたは **F11** で: 画面全体に映像だけを表示します。マウスを動かすと動画の操作バーが現れ、**Esc** または **F11** で終了します。
- **ダークまたはライト。** *表示* セクションの *テーマ*: *システム* は Windows のアプリの色設定に従い、または
  *ダーク* か *ライト* を選びます。
- **サイドバー** は端の細いハンドルでスライドして隠せます。クリックで表示 / 非表示、ハンドルをドラッグすると幅が変わります。
  ライブラリも同じで、上端をドラッグすると高さが変わり、サムネイルもそれに合わせて拡大縮小します。どちらの大きさも
  次回の起動まで記憶されます。ファイルの処理中はロックされ、*キャンセル* が使えます。
- **起動時** には、アイコン、名前、バージョン、状態の 1 行、動くバーを載せた小さなカードが表示され、メインウィンドウは
  最初のフレームの準備ができてから現れます。そのため起動時に空のウィンドウが出ることはありません。

## 最新の状態を保つ

アプリは起動のたびに、選んだチャネルの最新リリースを GitHub に問い合わせ、実行中のバージョンより新しければ知らせます。
チャネルは *情報* セクションの *更新チャネル* で選べます。**安定版**（正式リリースのみ）と **プレリリース版**
（正式リリース前にテスト用として公開されたビルドも含みます）の 2 つです。*起動時に更新を確認* でこの確認をオフにでき、
*更新を確認* ボタンを押せばいつでも手動で確かめられます。前回の確認結果はその下に表示されます。

新しいバージョンがあると、そのバージョン、公開日、リリースノートと 3 つのボタンを載せたウィンドウが開きます。
**今すぐ更新** はリリースの zip を `%LOCALAPPDATA%\VRChatDLSS5Cam\update` にダウンロードして展開し、アプリを終了して
プログラムのファイルを置き換え、もう一度起動します。設定、ライブラリ、そしてプログラムフォルダーにあるご自身の
`nvngx_dlssnr.dll` はそのまま残ります。**リリースページ** はブラウザーでそのリリースを開き、**あとで** はウィンドウを
閉じます。プログラムのフォルダーは書き込み可能である必要があり、`Program Files` の下のフォルダーは通常書き込めません。
その場合はアプリがその旨を伝えるので、リリースページから手動で更新してください。確認や更新に失敗したときは通知で
知らせます。

この `api.github.com` へのリクエスト（および更新を選んだときの `github.com` からのダウンロード）が、このアプリが行う
唯一のネットワークアクセスです。ほかには何も送信しません。ウィンドウなしの実行と `--process` の実行では、
自動の確認は行われません。

## 設定の説明

<details>
<summary>すべての設定（セクションごと）</summary>

| セクション | 設定 | 意味 |
|---|---|---|
| ソース | 入力ソース | *VRChat カメラ（Spout）*、*画像ファイル*、または *動画ファイル*。 |
| ソース | Spout 送信元 | 受信する Spout 送信元。VRChat のカメラは `VRCSender1` です。 |
| ソース | 処理解像度をカスタム指定 | 元のサイズではなく任意のサイズで処理します。DLSS 5 にそのサイズまでアップスケールさせることもできます。 |
| ソース | 元動画の仕様に合わせる | 動画のみ、既定でオン: 出力は元ファイルのコーデック（H.264 または HEVC）、フレームレート、平均ビットレートを使います。 |
| ソース | 保存形式 / ビットレート / 音声を保持 | *元動画の仕様に合わせる* がオフのとき: *MP4 (H.264)*、*MP4 (HEVC)*、または *PNG 連番*、エンコーダーのビットレート（5–200 Mbit/s）、音声トラックをコピーするかどうか。 |
| ソース | ハードウェアデコード | 動画を GPU でデコードします。色がおかしい、または開けないファイルがある場合はオフにしてください。 |
| ソース | ペーパーホワイト / ハイライト圧縮 | 浮動小数点（HDR）の Spout テクスチャのときのみ表示: ニューラルパスの前に適用する露出基準とハイライトの滑らかなロールオフ。 |
| DLSS 5 | DLSS 5（DLSSNR）を有効化 | ニューラルパスのオン / オフ。オフでランタイムを解放し、オンでファイルから読み込み直します。 |
| DLSS 5 | ランタイムのパス / 再読み込み | `nvngx_dlssnr.dll` の場所。*再読み込み* でファイルを読み込み直します。 |
| DLSS 5 | ホスト方式 | *直接（signed snippet）*: `nvngx_dlssnr.dll` を直接ホストします。*NGX コア*: NGX ランタイム経由で機能を作成します。 |
| DLSS 5 | プリセット / スタイル | ランタイムに渡すレンダープリセット（0–3）とスタイル（既定 / ナチュラル / シネマティック）。 |
| DLSS 5 | 強度 | ニューラルパス全体の強さ（0–2）。1 まではランタイム自身の強度、1 を超えるとアプリがニューラル結果と元画像との差を増幅します（アーティファクトが強調されることがあります）。0 では画像に手を加えません。 |
| DLSS 5 | グローバルトーン強度 / ローカルトーン強度 | グローバルとローカルのトーン強度（0–2）。1 を超えたときの規則は上と同じです（1 を超える強度のうち最も高い値が倍率になります）。 |
| DLSS 5 | ローカル構造強度 / スキン構造強度 | ディテール強調（0–2）。1 を超えたときの規則は同じです。スキン構造強度はランタイムの既定値のままにできます。 |
| DLSS 5 | 自動マスク / UI 補正 | 自動被写体マスク、UI セーフ処理。 |
| DLSS 5 | 撮影時のみニューラルパスを実行 | ライブ利用には遅すぎるカード向け: 撮影と撮影の間はニューラル・モーション・深度のパスがすべて休止し、GPU はほぼアイドルになります。撮影時はまず新しい 16 フレームでニューラルパスを実行し（深度ガイダンスがオンなら最初の深度推定の後から数えます）、それから保存します。静止画には影響しません。 |
| DLSS 5 | 入力露出 / トーン転送強度 / 色の強度 | 出力ブレンド。入力露出（0.25–4 倍）はネットワークが見る画像を拡大縮小し、後で元に戻されます。トーン転送強度と色の強度（0–2）は、ニューラルパスによる明るさと色の変化をどれだけ出力に反映するかを決めます。1 / 1 でニューラル結果を正確に再現し、0 で元画像を維持します。 |
| DLSS 5 | シャドウ強度 / ハイライトとグロー強度 | 出力ブレンド（0–2）: ニューラルパスによる暗くなる変化と明るくなる変化を、それぞれどれだけ出力に反映するか。1 / 1 = レンダリング通り。 |
| DLSS 5 | ニューラルパス解像度 | 縮小した画像（入力の 25–100 %）でニューラルパスを実行し、その変化を拡大してフル解像度の画像に加えます。値を下げると、最も細かいディテールと引き換えに GPU 負荷が減ります。ニューラルアップスケール中は使われません。 |
| 撮影 | 保存先 / 透明度（アルファ）を保持 / 元のフレームも保存 / グローバルホットキー / 自動撮影の間隔（秒） | 写真と動画をどこに、どのように保存するか。 |

## トラブルシューティング

- **「VRChat の Spout ストリームを待機中…」** – VRChat の Stream カメラで *Spout Stream* を有効にしてください。カメラは開いている必要があります。他の Spout 送信元は *Spout 送信元* ボックスに表示されます。
- **「nvngx_dlssnr.dll が見つかりません」** – ランタイムを `VRChatDLSS5Cam.exe` の隣にコピーするか、DLSS 5 セクションでそのパスを選択してください。
- **ニューラルレンダリングに失敗** – RTX 40 / 30 / 20 で通常のランタイムを使っている場合は想定どおりの動作です。そのビルドには RTX 50 向けのコードしか含まれておらず、アプリがエラーの下にその旨を表示します。改変ビルドは RenoDX の Discord サーバーで入手してください（*動作要件* を参照。本プロジェクトとは無関係です）。それ以外の場合、一部のランタイムビルドはより新しいドライバーを必要とします。`log.txt` で NGX の結果コードを確認し、*プリセット* 0 と *NGX コア* 方式を試してください。
- **ニューラルパスは動作中なのに、画像が真っ黒または変化しない** – アプリはニューラルの各フレームを入力と比較し、ランタイムが成功を報告しながら真っ黒または未変化の画像を返すと警告します（`log.txt`: "DLSSNR output check"）。DLSS 5 をいったんオフにしてからオンにし直すと、まっさらな状態からやり直せます。それでも続く場合、そのランタイムビルドはこの GPU では画像を生成できません。（*強度* が 0 のときは画像が変化しないのが正常で、警告は表示されません。）
- **アプリが起動しない / すぐに終了する** – `%LOCALAPPDATA%\VRChatDLSS5Cam\` を開き、`log.txt`（最後の行が失敗したステップ）と `crash.txt` を確認してください。Issue には両方のファイルを添付してください。
- **NGX 未初期化 / DLAA 非対応** – NGX ランタイムには NVIDIA GPU と最新のドライバーが必要です。DLSS 5 は *直接（signed snippet）* 方式で引き続き動作します。
- **深度推定が利用不可** – `onnxruntime.dll`、`onnxruntime_providers_shared.dll`、`DirectML.dll`、`models\depth_anything_v2_small_fp16.onnx` が実行ファイルの隣にある必要があります（いずれもリリースパッケージに含まれています）。推定器の準備が整うまでアプリはゼロ深度を使い、その状態は *フレームガイダンス* の下に表示されます。
- **オプティカルフローが利用不可** – `log.txt` に "NVOF unavailable, falling back to block matching" と出る場合は、GeForce ドライバーを更新してください。それまではブロックマッチングが使われます。*フレームガイダンス* の下の状態ドットが、どのソースが有効かを示します。
- **動画のプレビューが真っ黒** – 多くの映像は黒からのフェードで始まります。プレビューはそのフレームを飛ばし、表示中のフレームがまだ暗いときは画像の下にその旨を表示します。シークバーか矢印キーで先に進んでください。
- **動画ファイルが開けない / エンコーダーがない** – 対応形式は Windows にインストールされているコーデックで決まります。HEVC ファイルには *HEVC ビデオ拡張機能*（Microsoft Store）を、Windows N / KN には *Media Feature Pack* をインストールしてください。H.264 エンコーダーがない場合は出力に *PNG 連番* を選びます。GPU デコーダーが受け付けないファイルには、*ハードウェアデコード* をオフにすると効果があります。
- **フレームレートが低い** – DLAA をオフにする、深度更新間隔を大きくするか深度ネットワーク解像度を下げる、ニューラルパス解像度を下げる、または処理レート上限を設定します。オプティカルフローのグリッドは 4 px のままにしてください（2 px と 1 px は 4K では大幅に重くなります）。ログには 15 秒ごとに、各ステージのコストを示す `Perf:` 行が出力されます。
- **更新をインストールできない** – プログラムのフォルダーは書き込み可能である必要があり、`Program Files` の下のフォルダーは通常書き込めません。アプリをご自身のフォルダーに移すか、リリースページから新しいバージョンをダウンロードして手動でファイルを置き換えてください。設定とライブラリはそのまま残ります。

## ソースからのビルド

必要なもの: Visual Studio 2022（MSVC v143、Windows 10 SDK）と CMake 3.21 以降。

```powershell
git clone https://github.com/AlanBacker/VRChat-DLSS5-Cam.git
cd VRChat-DLSS5-Cam
cmake -S . -B build -A x64
cmake --build build --config Release --parallel
```

構成ステップでは、NVIDIA の公開 GitHub リポジトリから NVIDIA DLSS SDK（ヘッダー、`nvsdk_ngx_s.lib`、`nvngx_dlss.dll`）を、
NuGet から ONNX Runtime（DirectML ビルド）と DirectML を、Hugging Face から Depth Anything V2 Small FP16 モデルを
ダウンロードします（`-DVDC_FETCH_DEPTH_MODEL=OFF` でモデルをスキップします）。すべてのダウンロードはハッシュ検証されます。
シェーダーは実行時にコンパイルされるため、シェーダーツールチェーンは不要です。DLSS 5 ランタイムがビルドやパッケージに含まれることは決してありません。

## 仕組み

<details>
<summary>パイプラインと設計メモ</summary>

```
VRChat Stream Camera ──Spout──▶ D3D11on12 receive ──▶ convert (sRGB / resize)
      ▶ NVIDIA Optical Flow (forward + backward) / block matching ──▶ motion vectors + confidence
      ▶ Depth Anything V2 (ONNX Runtime DirectML, every N frames) ──▶ normalized depth, reprojected in between
      ▶ [DLAA] ──▶ DLSSNR (nvngx_dlssnr.dll) ──▶ composite / compare ──▶ preview + PNG capture
Video file ──Media Foundation──▶ decode (GPU) ──▶ same pipeline, one frame at a time ──▶ MP4 (H.264 / HEVC + AAC) or PNG sequence
```

本アプリは、DLSS 5 ニューラルレンダリングスニペットを NGX ランタイムの外側でホストします。DLL を直接読み込み、
そのモジュール名チェックを満たし、`DLSSNR.*` NGX パラメーター規約を使って D3D12 キュー上で機能を作成・評価します
（`src/ngx/DlssnrFeature.cpp`）。パラメーターは RenoDX の DLSS 5 アドオンが公開しているものと同じ一式です。

ガイダンスの方式は動画入力向けに組まれています。同解像度の SDR 入力、順方向と逆方向のベクトルが一致しない箇所で
信頼度を下げるハードウェアオプティカルフロー、Depth Anything V2 による単眼深度を（2 / 98 パーセンタイルで）反転相対深度に
正規化し推論の合間はモーションベクトルに沿って移動させたもの、そしてフレームごとの履歴リセットなし、という構成です。
すべて独立した MIT 実装です（`src/gfx/Pipeline.cpp`、`src/gfx/DepthEstimator.cpp`、`src/gfx/Shaders.cpp`）。
オプティカルフローエンジンは専用のネイティブ D3D11 デバイス上で動作し、フレームとベクトルは共有フェンスで順序付けられた
NT ハンドル共有テクスチャを通して D3D12 に渡されます（`src/gfx/NvOpticalFlow.cpp`）。

2 つのスレッドが GPU を共有します。処理スレッドは Spout レシーバー（またはファイル）、パイプライン、専用の D3D12 キューを持ち、
インターフェーススレッドはウィンドウ、ImGui、高優先度のプレゼントキューを持ちます。完成した画像はキュー間のフェンス待機を伴う
表示バッファを通して受け渡されるため、プレビューは常に最新の完成フレームを表示し、ウィンドウがニューラルパスを待つことは
ありません（`src/core/App.cpp`、`src/gfx/Device.cpp`）。静止画は WIC でデコードされ（EXIF の向きを適用）、一度だけ
アップロードされて、時間方向のネットワークが安定するまで同じパイプラインをゼロモーションで数パス通ります。

動画ファイルは、Media Foundation のソースリーダーが専用スレッドでデコードし（DXGI デバイスマネージャー経由のハードウェア
デコーダー、ソフトウェアへのフォールバックあり）、短いフレームキューに入れます。処理スレッドはパイプラインに 1 フレームずつ渡し、
そのフレームの結果の読み戻しを要求します。読み戻しはフレーム順に集められてライターに渡されるため、ニューラルパスが
フレーム間隔より長くかかってもフレームの欠落や重複は起きません。ライターは専用スレッドで各フレームを NV12 に変換し、
デコードした音声サンプルとともに Media Foundation のシンクライター（可能ならハードウェアエンコーダー）に送ります
（`src/core/VideoSource.cpp`、`src/core/VideoWriter.cpp`）。

</details>
