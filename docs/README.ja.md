# VRChat DLSS5 Cam

[English](../README.md) · [简体中文](README.zh-CN.md) · **日本語** · [한국어](README.ko.md)

VRChat DLSS5 Cam は、VRChat のカメラ映像に GeForce RTX 上で NVIDIA の **DLSS 5 ニューラルレンダリング** を適用し、
その結果をロスレス PNG として記録する Windows 向けアプリケーションです。ディスク上の画像や動画も同一の処理系を通り、
単体処理と一括処理の双方に対応します。通常の Windows アプリケーションであり、VRChat のプロセスには一切干渉せず、
Mod も必要としません。

## 主な機能

- **ライブカメラ。** VRChat の Stream カメラを Spout 経由で受け取り、DLSS 5 適用後の映像をリアルタイムに
  プレビューします。グローバルホットキー（`Ctrl+Alt+P`）は VRChat が前面にある状態でも有効で、そのまま
  ロスレス PNG を保存できます。
- **画像と動画ファイル。** スクリーンショットや録画をウィンドウにドロップし、パラメーターを調整したうえで
  書き出せます。出力形式は、画像が PNG、動画が MP4（H.264 / HEVC、音声トラックを保持）または PNG 連番です。
- **一括処理。** 読み込んだファイルはプレビュー下部のライブラリに集約され、選択した分をまとめて処理できます。
  共通パラメーターに加えてファイル単位の個別パラメーターにも対応し、処理前の回転・反転・切り抜きも行えます。
- **本物の DLSS 5 ガイダンス。** NVIDIA Optical Flow によるモーションベクトルと Depth Anything V2 による
  深度マップをネットワークへ供給するため、動画とライブ映像はゲーム内と同等の時間的手掛かりを伴って処理されます。
  前段には任意で DLAA パスを挿入し、先にエッジを整えることもできます。
- **比較と検証。** ワイプ、左右分割、オリジナル表示に加え、ホイールによるズーム、ドラッグによるパン、全画面表示に
  対応し、処理前後の差分を等倍で確認できます。
- **実用面の作り込み。** Windows の設定に追従するダーク／ライトテーマ、履歴付きのアンドゥ・リドゥ、任意の名前で
  保存できるプリセット、全設定を対象とする検索、大きさを変えられるレイアウト、更新の自動確認、4 言語
  （English、简体中文、日本語、한국어）の UI、UI 専用スレッドによる安定した操作感、スクリプト実行向けの
  コマンドラインを備えます。

## 動作環境

| | |
|---|---|
| Windows | Windows 10 21H2 または Windows 11、64 ビット |
| グラフィックカード | NVIDIA GeForce RTX。**RTX 50** シリーズと **RTX 40 / 30 / 20** シリーズにはそれぞれ対応するランタイムのビルドがアーカイブに同梱されているため（次の行を参照）、どの世代でも追加のファイルは不要です。**AMD Radeon RX 7000 / 9000** は Radeon 版（`VRChatDLSS5Cam-win64-amd.zip`）で対応します。ニューラルパスは DLSS-NR-on-AMD（別プロジェクト、アプリ内からインストール可能）が担います（*AMD Radeon カード* を参照）。他社製カードも拒否しません。ビューアーおよび録画ツールとして動作します。DLAA とハードウェアオプティカルフローは NVIDIA 専用のままで、モーションはブロックマッチングが引き継ぎます。 |
| DLSS 5 ランタイム | 同梱。アーカイブには `nvngx_dlssnr.dll` 310.8.0.0 が 2 つのビルドで入っています。`runtimes\blackwell\` はゲームに同梱されている通常のビルド（RTX 50）、`runtimes\universal\` は同じランタイムをコミュニティが RTX 40 / 30 / 20 向けに適合させたビルドです。起動時に搭載カードに合うビルドが選ばれ、失敗した場合はもう一方が試されます。どちらのファイルも NVIDIA のソフトウェアであり NVIDIA の条件に従います。本プロジェクトの MIT ライセンスのソースには含まれません（`THIRD_PARTY_NOTICES.md` を参照）。ほかの場所から入手するものはありません。 |
| VRChat | Stream カメラに *Spout Stream* オプションがあるビルド（デスクトップまたは VR）。ライブカメラにのみ必要です。 |
| 動画ファイル | Windows Media Foundation（Windows の一部）。N / KN エディションには *Media Feature Pack* が必要です。HEVC ファイルには Microsoft Store の *HEVC ビデオ拡張機能* が必要な場合があります。 |

## 導入手順

| お使いのグラフィックカード | ダウンロード | 補足 |
|---|---|---|
| NVIDIA GeForce RTX 20 / 30 / 40 / 50 | `VRChatDLSS5Cam-win64.zip` | DLSS 5 ランタイムはアーカイブに同梱されています。 |
| AMD Radeon RX 7000 / 9000 | `VRChatDLSS5Cam-win64-amd.zip` | Radeon 版。初回起動時に DLSS-NR-on-AMD のインストーラーを取得します。現バージョンで期待できることは [AMD Radeon カード](#amd-radeon-カード) を参照してください。 |

1. [最新リリース](https://github.com/AlanBacker/VRChat-DLSS5-Cam/releases/latest) から `VRChatDLSS5Cam-win64.zip` をダウンロードし、任意の場所に展開します。（Radeon カードの場合は代わりに `VRChatDLSS5Cam-win64-amd.zip` を。下記 *AMD Radeon カード* を参照。）
2. ほかにコピーするものはありません。DLSS 5 ランタイムはアーカイブの `runtimes\` 以下に、RTX 50 向けと RTX 40 / 30 / 20 向けの 2 つのビルドで入っています。アプリケーションは起動時に搭載カードに合うビルドを選び、失敗した場合はもう一方に切り替えます。使用中のビルドは DLSS 5 セクションの*ランタイム*の隣に表示され、パスは `log.txt` に記録されます。

   ```
   VRChatDLSS5Cam.exe
   runtimes\blackwell\nvngx_dlssnr.dll   RTX 50
   runtimes\universal\nvngx_dlssnr.dll   RTX 40 / 30 / 20
   runtimes\other\nvngx_dlssnr.dll       他社製向けランタイム（同梱なし。Radeon は Radeon 版を使用）
   ```

   代わりに自分のファイルを使うこともできます。`VRChatDLSS5Cam.exe` と同じ場所の `nvngx_dlssnr.dll` はカードに合うビルドの次に試され、任意のファイルを *DLSS 5 ニューラルレンダリング → ランタイムのパス* から選択できます。
3. VRChat で**カメラ**を開き、**Stream** モードに切り替えて、その設定で **Spout Stream** を有効にします。
4. `VRChatDLSS5Cam.exe` を起動します。DLSS 5 を適用したカメラ映像がプレビューに表示され、*DLSS 5（DLSSNR）を有効化* スイッチの隣のバッジが *動作中* になります。
5. VRChat で構図を決めて **Ctrl+Alt+P**（または *撮影* ボタン）を押します。PNG は `Pictures\VRChat DLSS5 Cam` に保存されます。

ライブカメラについて

- ストリームの解像度は VRChat が決めます。VRChat の `config.json` で `camera_spout_res_width` / `camera_spout_res_height` を上げるとより鮮明な入力が得られ、アプリケーションは自動的に追従します。
- ニューラルパスがライブプレビューに対して重すぎるカードでは、DLSS 5 セクションの *撮影時のみニューラルパスを実行* が有効です。プレビューは元の映像のままとなり、ニューラル・モーション・深度のパスはすべて休止し、撮影のたびに写真のためだけニューラルパスが実行されます。
- *表示* セクションの *処理レート上限* は、毎秒処理するカメラフレームの数を制限し、GPU を VRChat のために空けておきます。

## AMD Radeon カード

Radeon 版（`VRChatDLSS5Cam-win64-amd.zip`）は、[DLSS-NR-on-AMD](https://github.com/danielblnc/DLSS-NR-on-AMD) を通じて Radeon カードでニューラルパスを実行します。DLSS-NR-on-AMD は
Daniel Blanco 氏による別プロジェクトで、FSR を使うプログラムに取り付くことで DLSS 5 ニューラルレンダリングを AMD ハードウェアで動かします。本アプリにはその内容は
一切含まれていません。Radeon 版は取り付き先となる FSR コンテキスト（AMD の FidelityFX API、`amd_fidelityfx_dx12.dll`、MIT）をホストし、
ボタンが押されたときにそのプロジェクト自身のリリースページからインストーラーを取得します。そのプロジェクトの
[ライセンス](https://github.com/danielblnc/DLSS-NR-on-AMD/blob/master/LICENSE)は個人的・非商用の利用を許可し、再配布と改変を禁じているため、
インストーラーが本アプリのアーカイブに入ることはありません。

1. [最新リリース](https://github.com/AlanBacker/VRChat-DLSS5-Cam/releases/latest) から `VRChatDLSS5Cam-win64-amd.zip` をダウンロードし、任意の場所に展開します。実行ファイルの隣に
   `amd_fidelityfx_dx12.dll` と RTX 50 向けビルドの `nvngx_dlssnr.dll` が入っています（手順 2 のインストーラーが後者を自身の重みに変換します）。
   NVIDIA 専用のファイル（`nvngx_dlss.dll`、`runtimes\`）は含まれていません。GeForce 版は Radeon カード上で起動すると **Radeon 版を入手…** を
   表示し（コマンドラインの `--edition amd` も同じ）、アップデートと同じ手順で自身のファイルを置き換えます。
2. `VRChatDLSS5Cam.exe` を起動します。スタートカードと DLSS 5 セクションに **DLSS-NR-on-AMD をインストール…** が、そのライセンスへのリンクとともに
   表示されます。一度押すと `dlssnr_on_amd_setup.exe` がプログラムフォルダーにダウンロードされ、バックグラウンドで実行されます。フォルダーと、実行ファイル
   向けに提案される DLL 名を自動で受け入れるので、ウィンドウもキー操作も要りません。終わるとアプリは自動的に再起動し、DLSS 5 セクションに
   *ランタイム: 読み込み済み FSR … · FSR ホスト* と *DLSS-NR-on-AMD v…: 読み込み済み（version.dll）· 最新です* が表示され、*DLSS 5 を有効化* スイッチの
   隣のバッジが *有効* になります。フォルダーに管理者権限が必要な場合や、移植が対応しないカードの場合は、インストーラーが代わりに独自のウィンドウを開き、
   そのメッセージが見えるようにします。

DLSS 5 セクションはインストール済みのリリースと最新リリースを並べて示します。DLSS-NR-on-AMD の新しいリリースが出るとセクションがそれを伝え、
ボタンが **… に更新** になります。これと **インストーラーを再実行…** はインストーラーを取得してそのウィンドウを開き、そこで **U** で更新（設定と重みを保持）、
**R** で削除します。このバージョンより前に行ったインストールは、実行ファイルの隣のインストーラーファイルから認識されます。

この方式では、1 までのニューラルパスの強度は DLSS-NR-on-AMD のもので、そのオーバーレイ（**End** キー）で設定します。オーバーレイの *Mode* は
inline のままにします（保存されるフレームに必要です。後述）。本アプリの *プリセット*、*スタイル*、各強度は渡されません。
パスの後段で働くコントロール（*出力ブレンド*、1 を超える強度、*ニューラルパス* の解像度）は通常どおり働きます。DLSS-NR-on-AMD には Windows 11、
Radeon RX 7000 または RX 9000、Adrenalin 26.1.1 以降が必要です。最新の要件はそのリリースページを参照してください。*詳細* の *ホスト方式* で方式を
手動選択できます（*自動* は Radeon で FSR ホスト、GeForce で直接方式を選びます）。

Radeon 版は RX 9060 XT 上で動作を確認しています（720p と 4K の静止画、動画ファイル、コマンドラインからのバッチ処理、そしてライブの VRChat
カメラ映像。フレームレートは GeForce カードより低くなります。下記の一覧を参照）。DLSS-NR-on-AMD のインストーラーが書き込む inline の待ち時間は 200 ms でゲーム向けの値で、これを超えた
フレームは前のフレームの結果を表示します。本アプリはインストール後（起動時にファイルにまだ低い値が残っている場合は一度だけ自動的に再起動して）
`dlssnr_on_amd.ini` の `InlineWaitMs` を 1000 に引き上げ、保存される画像や動画のフレームがそのフレーム自身の結果を持つようにし、`Inline` は 1 の
ままにします。そのファイルの他の部分は変更しません。`log.txt`（`%LOCALAPPDATA%\VRChatDLSS5Cam\`）には
実行ファイルの隣にある DLSS-NR-on-AMD のファイルが記録され、末尾にはそのプロジェクト自身のログ（プログラムフォルダーの `dlssnr_on_amd.log`）の
最後の数行が付きます。これを添えた報告を issue でお待ちしています。

### 現バージョンで Radeon に期待できること

- **カード。** Windows 11 上の Radeon RX 7000 / RX 9000（Adrenalin 26.1.1 以降）、すなわち DLSS-NR-on-AMD が対応するカードです。作者のテストは
  RX 9060 XT で行いました。それより古い Radeon では FSR ホストは動きますが、このポートのネットワークは働かず、画像はそのまま返ります。
- **動作するもの。** 静止画、動画ファイル、バッチキュー、撮影とタイムラプスを含むライブの VRChat カメラ映像、深度ネットワーク、パス後の
  コントロール（*出力ブレンド*、1 を超える強度、*ニューラルパス解像度*）、アップデート、エディションの切り替え。
- **遅い点。** DLSS-NR-on-AMD はネットワークを inline で実行し、フレームはその完了を待ちます。RX 9060 XT では 720p で約 25 ms、4K で約 180 ms
  なので、4K のライブ映像は毎秒数フレームになります。*ニューラルパス解像度* の *最大解像度* 上限と *処理レート上限* でライブ映像は滑らかに
  保てます。保存される画像や動画の結果は同じで、時間がかかるだけです。
- **ハードウェアオプティカルフローなし。** オプティカルフローエンジンは GeForce ドライバーのものです。Radeon ではモーションベクトルは GPU
  ブロックマッチングから得られ、速い動きではより粗くなります。*フレームガイダンス* の下の状態ドットがそれを示します。
- **強度とプリセット。** このポートは *プリセット*、*スタイル*、1 までの強度を自前のオーバーレイ（**End** キー）で保持します（前述）。
  そのため本アプリでこれらのスライダーを動かしても、既存の結果をすぐに合成し直すだけで（1 を超える値は合成で反映されます）、画像をパスに通し直すことはありません。
  Radeon ではそれに 4K で約 4 秒かかるうえ、絵は変わらないからです。
- **深度ネットワークとポートは交代で GPU を使います。** ポートのネットワークと深度ネットワーク（DirectML）は GPU を同時に使えません。深度ネットワークのウォームアップと
  重なったニューラルパスは 0.17 秒から 2.7 秒に伸び、ドライバーの 2 秒制限を超えてグラフィックスデバイスが失われました（ドライバーが再起動し、アプリを起動し直す必要があります）。
  v1.5.0 からは各ニューラルパスの前に深度ネットワークの完了を待つため、両者は重なりません。画像の最初のパスは深度ネットワークの準備ができてから始まります。
  以前 4K のバッチ処理で見られた 1 フレーム 3 秒の停止（ポートのログの watchdog spike）も同じ重なりでした。
- **アイドル時の負荷。** 画像がパスを終えると GPU はアイドルになります（RX 9060 XT で約 2 %、GeForce と同じ）。ただし最初のニューラルパスからアプリを閉じるまで、
  CPU コアが 1 つ使われ続けます。DLSS-NR-on-AMD のスレッドが GPU を全速でポーリングしているためです（inline モード）。このスレッドはポート側のもので、FSR コンテキストを解放しても止まりません。

**予定：** 本アプリ独自のオプティカルフローパス。AMD FidelityFX SDK のオプティカルフロー（MIT）を移植し、Radeon ではブロックマッチングを置き換え、
GeForce では第二のソースとします。

## 画像と動画ファイル

ファイルはウィンドウへのドロップ、または *ソース* セクションの *画像を開く…* / *動画を開く…* から読み込めます。
画像はプレビューに表示され、すべてのスライダーがすぐにそれへ効きます。*開く…* の横の ✕ ボタンはファイルを閉じ、
処理が止まり、プレビューが空になり、ファイルはライブラリに残ります。**処理して PNG を保存**（画像）、
**処理して動画を保存**（動画）、またはホットキーを押すと、結果が元のファイルと同じ場所に
`<name>_DLSS5_<w>x<h>.png`、`.mp4`、または PNG フレームのフォルダとして書き出されます。

<p align="center">
  <img src="images/video.png" width="900" alt="プレビューで開いた動画。ワイプ比較と、画像の下の再生・コマ送り・範囲のコントロール">
</p>

動画の場合、プレビュー下のコントロールでファイルをパイプライン全体を通して再生・一時停止し、1 フレームずつコマ送りでき、
シークバー上のカーソル位置のフレームが小さな画像で表示されます。*ここを開始点に* / *ここを終了点に* は処理（と音声）を
範囲に限定し、*動画全体* がその限定を解除します。既定では出力は元動画に合わせられ、コーデック、フレームレート、
ビットレートが同じになります。*元動画の仕様に合わせる* をオフにすると、H.264、HEVC、PNG 連番とビットレートを
個別に選択できます。*撮影* セクションには、現在の設定でそのファイルにかかるおおよその時間が表示されます。

## 一括処理

開いたりドロップしたりしたファイルはすべて、プレビュー下の **ライブラリ** に並びます（*ファイルを追加…* と
*フォルダーを追加…* でさらに追加できます）。サムネイルの **ダブルクリック** でそのファイルがプレビューで開き、
スライダーを調整できます。シングルクリックはそのファイルだけを選択し、**Ctrl+クリック** で 1 つ追加または解除、
**Shift+クリック** で最後にクリックしたファイルからの範囲選択、何もない場所のドラッグで矩形選択、何もない場所の
クリックで選択解除になります。各サムネイルのチェックボックスでも切り替えられ、**Ctrl+A** は読み込めるファイルを
すべて選択します。マウスがライブラリの上にあるとき（または最後のクリックがライブラリ内だったとき）の **Delete** キーは、
選択した項目をライブラリから外します。ディスク上のファイルは削除されません。*選択項目を処理* または *すべて処理* で
ファイルが順番に処理され、各サムネイル上のバーが進捗を示し、処理後も状態が表示されたまま残ります。

サムネイルの右クリックでメニューが開き、エクスプローラーでのファイル表示、ライブラリからの除外、別ウィンドウでの
**そのファイル専用の DLSS 5 パラメーター** の設定が行えます。複数のファイルを選択した状態では、同じメニューに
*N 件のファイルに個別パラメーター…* が現れ、すべてのファイルに一度に値を設定します。その後は各ファイルが自分の値を
保持します。

ライブラリのファイルをプレビューしている間は、画面上の小さなツールバーで **回転・反転・切り抜き** が行えます。
左または右への 90 度回転、水平または垂直の反転、あるいは切り抜き枠を出して角や辺をドラッグ（枠の内側のドラッグで移動）し、
**Enter** または *適用* で確定、**Esc** で取り消します。最後のボタンはファイルを元の状態に戻します。各ファイルは自分の
向きと切り抜きを保持し、処理と保存結果には回転・切り抜き後の画像が使われ、各操作はヒストリーに記録されるため
元に戻せます。ライブ映像にも切り抜きを除く同じツールバーがあり、VRChat カメラ映像の回転や反転はプレビュー・撮影・
タイムラプスのすべてに適用され、次回起動時も保持されます。ツールバー自体も動かせます。左端のグリップをドラッグして移動し、画面の端の外へ
離すか右端の矢印を押すと、その端に収納されます。端に残る小さなタブで戻せます。位置も次回起動時に保持されます。

## インターフェースの使い方

- **日常的な作業は 3 つのセクションが担います。** *ソース*（何を入力するか）、*DLSS 5 ニューラルレンダリング*
  （どう仕上げるか）、*撮影*（どこに保存するか）で、その後に *表示* と *情報* が続きます。DLSS 5 セクションの
  *詳細* スイッチは、トーンと構造のスライダー、出力ブレンド、*撮影* の後に入る *フレームガイダンス* と
  *DLAA プリパス*、そして *情報* の前に入るタイマー付きの *内部情報* の表示 / 非表示を切り替えます。
- **比較** はワイプ（プレビュー内のハンドルをドラッグ）、左右並べて表示、またはオリジナルで行います。ワイプは
  インターフェース自身のフレームレートでマウスに追従するため、動画の再生が遅くても引っかかりません。プレビュー上の
  マウスホイールはカーソル位置を中心にズームし、ドラッグで移動、ダブルクリックでウィンドウに合わせた表示に戻ります。
- **プリセット** は DLSS 5 セクションで作成します。*+* で現在の値に名前を付けて保存し、一覧のクリックで適用、
  各項目は現在の値での上書き、名前の変更、削除ができます。設定フォルダの `presets.txt` に保存されます。
- **検索** はサイドバー上部の欄で行い、一致するコントロールとそのセクションだけが残ります。**Esc** または ✕ で消去します。
- **元に戻す・やり直し** は設定のすべての変更と、ライブラリへのファイルの追加・削除を対象とし、**Ctrl+Z** / **Ctrl+Y**
  またはトップバーの 2 つの矢印で操作します。矢印の隣にある時計ボタンで **ヒストリー** が開き、記録されたすべての変更が
  一覧になります（*強度: 1.2*、*photo.png を追加*、*3 個のファイルを外した*、*photo.png: 個別の値*）。現在の状態が
  強調表示され、元に戻した状態はその後ろに淡色で並びます。項目をクリックするとその状態に移り、新しい変更を加えるまで
  後ろの項目は残るため、前後に自由に行き来できます。最大 100 ステップまで保持されます。
- **全画面表示** はプレビューの隅のボタンまたは **F11** から入り、画面全体に映像だけを表示します。マウスを動かすと
  動画の操作バーが現れ、**Esc** または **F11** で終了します。出入りはフェードし、*ライブ*・*画像*・*動画* の切り替えも
  同様にフェードします。
- **ダークまたはライト。** *表示* セクションの *テーマ*: *システム* は Windows のアプリの色設定に従い、*ダーク* と
  *ライト* を直接選ぶこともできます。
- **サイドバー** は端の細長いバーの後ろにスライドして隠れ、ライブラリの上にも同じ形のバーがあります。**バーのクリック** で
  パネルが折りたたまれたり開いたりします。ドラッグの対象は **バーの内側の縁にある細い線** で、マウスを載せると青く光り、
  カーソルがサイズ変更の矢印に変わります。この線の **ドラッグ** でサイドバーの幅やライブラリの高さが変わり、
  サムネイルもそれに合わせて拡大縮小します。どちらの大きさも次回の起動まで記憶されます。ファイルの処理中はロックされ、
  *キャンセル* が使えます。
- **ヘルプ** はワンクリックです。トップバーの *?* ボタン（または *情報* の *ドキュメント*）が、インターフェースの
  言語でこのガイドを開きます。
- **起動時** には、アイコン、名前、バージョン（プレリリース版では *Pre-release* の印付き）、状態の 1 行、動くバーを載せた
  小さなカードが表示され、メインウィンドウは最初のフレームの準備ができてからフェードインします。そのため起動時に空の
  ウィンドウが出ることはありません。前回のファイルが再び開くのは、*表示* セクションの *起動時に前回のファイルを開く*
  （既定ではオフ）がオンのときだけです。

## アップデート

アプリケーションは起動のたびに、選択したチャネルの最新リリースを GitHub に問い合わせ、実行中のバージョンより
新しければ知らせます。チャネルは *情報* セクションの *更新チャネル* で選べます。**安定版**（正式リリースのみ）と
**プレリリース版**（正式リリース前にテスト用として公開されたビルドも含みます。正式リリースもこのチャネルに届き、更新ウィンドウは
各リリースを *正式リリース* か *プレリリース* かで示します）の 2 つです。*起動時に更新を確認* で
この確認をオフにでき、*更新を確認* ボタンからはいつでも手動で実行できます。前回の確認結果はその下に表示されます。

新しいバージョンがある場合、そのバージョン、公開日、リリースノートと 3 つのボタンを載せたウィンドウが開きます。
**今すぐ更新** はリリースの zip を `%LOCALAPPDATA%\VRChatDLSS5Cam\update` にダウンロードして展開し、アプリケーションを
終了してプログラムのファイルを置き換え、もう一度起動します。設定とライブラリはそのまま残り、`runtimes\` 以下の
同梱ランタイムはリリースのものに置き換えられ、実行ファイルの隣に置いた自分のランタイムファイルはそのまま残ります。**リリースページ** はブラウザーでそのリリースを開き、**あとで** はウィンドウを
閉じます。プログラムのフォルダーは書き込み可能である必要があり、`Program Files` の下のフォルダーは通常書き込めません。
その場合はアプリケーションがその旨を伝え、リリースページからの手動更新に切り替えられます。確認や更新に失敗したときは
通知で知らせます。

この `api.github.com` へのリクエスト（および更新を選んだときの `github.com` からのダウンロード）が、このアプリケーションが
行う唯一のネットワークアクセスです。ほかには何も送信しません。ウィンドウなしの実行と `--process` の実行では、
自動の確認は行われません。

## トラブルシューティング

- **「VRChat の Spout ストリームを待機中…」** – VRChat の Stream カメラで *Spout Stream* が有効になっている必要があり、カメラも開いている必要があります。他の Spout 送信元は *Spout 送信元* ボックスに表示されます。
- **「ランタイムのファイルがありません」** – アーカイブが完全に展開されていません。`runtimes\blackwell\nvngx_dlssnr.dll` と `runtimes\universal\nvngx_dlssnr.dll` は `VRChatDLSS5Cam.exe` の隣に置かれるものです。展開し直すか、*ランタイムのパス* でランタイムファイルを選択します。
- **ニューラルレンダリングに失敗** – アプリケーションは自動的にもう一方の同梱ビルドに切り替え、通知でその旨を伝えます。どちらのビルドも起動しない場合はエラーの下にその旨が表示されます。まずはより新しいグラフィックドライバーを試す価値があります。`log.txt` に NGX の結果コードが記録されており、*プリセット* 0 と *NGX コア* 方式を試す価値もあります。Radeon カードでは、ニューラルパスは Radeon 版と DLSS-NR-on-AMD で動作します（*AMD Radeon カード* を参照）。
- **FSR ホストは動作しているのに画像が変化しない** – DLSS-NR-on-AMD がこのプロセスに取り付いていません。DLSS 5 セクションに *DLSS-NR-on-AMD: 未読み込み* と表示されます。そこでインストールしてください（**DLSS-NR-on-AMD をインストール…**）。インストーラーが終わるとアプリは自動的に再起動します。インストール済みなのに読み込まれない場合はインストーラーを再実行してください。読み込まれているのに変化がない場合は、オーバーレイ（**End** キー）を開いて有効になっているか確認し、もう一方の *Mode* を試してください。そのログ（プログラムフォルダーの `dlssnr_on_amd.log`。最後の数行は `log.txt` の末尾にも付きます）に何をしたかが書かれています。この移植は独自の要件を持つ別プロジェクトです。
- **amd_fidelityfx_dx12.dll がない** – FSR ホスト方式には実行ファイルの隣にそのファイルが必要です。Radeon 版（`VRChatDLSS5Cam-win64-amd.zip`）に同梱されています。
- **ニューラルパスは動作中なのに、画像が真っ黒または変化しない** – アプリケーションはニューラルの各フレームを入力と比較し、ランタイムが成功を報告しながら真っ黒または未変化の画像を返すと警告します（`log.txt`: "DLSSNR output check"）。DLSS 5 をいったんオフにしてからオンにし直すと、まっさらな状態からやり直せます。それでも続く場合、そのランタイムビルドはこの GPU では画像を生成できません。（*強度* が 0 のときは画像が変化しないのが正常で、警告は表示されません。）
- **アプリケーションが起動しない / すぐに終了する** – `%LOCALAPPDATA%\VRChatDLSS5Cam\` に `log.txt`（最後の行が失敗したステップ）と `crash.txt` があります。Issue にはこの 2 つのファイルを添付します。
- **NGX 未初期化 / DLAA 非対応** – NGX ランタイムには NVIDIA GPU と最新のドライバーが必要です。DLSS 5 は *直接（signed snippet）* 方式で引き続き動作します。
- **深度推定が利用不可** – `onnxruntime.dll`、`onnxruntime_providers_shared.dll`、`DirectML.dll`、`models\depth_anything_v2_small_fp16.onnx` が実行ファイルの隣にある必要があります（いずれもリリースパッケージに含まれています）。推定器の準備が整うまではゼロ深度が使われ、その状態は *フレームガイダンス* の下に表示されます。
- **オプティカルフローが利用不可** – Radeon カードでは想定どおりの動作です。オプティカルフローエンジンは GeForce ドライバーの一部で Radeon には相当するものがないため、ブロックマッチングが使われ、*フレームガイダンス* の下の状態ドットがそれを示します。GeForce カードで `log.txt` に "NVOF unavailable, falling back to block matching" と出る場合は、GeForce ドライバーの更新が必要です。それまではブロックマッチングが使われます。
- **動画のプレビューが真っ黒** – 多くの映像は黒からのフェードで始まります。プレビューはそのフレームを飛ばし、表示中のフレームがまだ暗いときは画像の下にその旨を表示します。シークバーか矢印キーで先に進めば解消します。
- **動画ファイルが開けない / エンコーダーがない** – 対応形式は Windows にインストールされているコーデックで決まります。HEVC ファイルには *HEVC ビデオ拡張機能*（Microsoft Store）が、Windows N / KN には *Media Feature Pack* が必要です。H.264 エンコーダーがない場合は出力に *PNG 連番* を選べます。GPU デコーダーが受け付けないファイルには、*ハードウェアデコード* をオフにすると効果があります。
- **フレームレートが低い** – DLAA をオフにする、深度更新間隔を大きくするか深度ネットワーク解像度を下げる、ニューラルパス解像度を下げる、または処理レート上限を設定します。オプティカルフローのグリッドは 4 px のままが適切です（2 px と 1 px は 4K では大幅に重くなります）。ログには 15 秒ごとに、各ステージのコストを示す `Perf:` 行が出力されます。
- **更新をインストールできない** – プログラムのフォルダーは書き込み可能である必要があり、`Program Files` の下のフォルダーは通常書き込めません。アプリケーションをユーザー権限のフォルダーに移すか、リリースページから新しいバージョンをダウンロードして手動でファイルを置き換えます。設定とライブラリはそのまま残ります。

## ソースからのビルド

必要なもの: Visual Studio 2022（MSVC v143、Windows 10 SDK）と CMake 3.21 以降。

```powershell
git clone https://github.com/AlanBacker/VRChat-DLSS5-Cam.git
cd VRChat-DLSS5-Cam
cmake -S . -B build -A x64
cmake --build build --config Release --parallel
```

構成ステップでは、NVIDIA の公開 GitHub リポジトリから NVIDIA DLSS SDK（ヘッダー、`nvsdk_ngx_s.lib`、`nvngx_dlss.dll`）を、
NuGet から ONNX Runtime（DirectML ビルド）と DirectML を、Hugging Face から Depth Anything V2 Small FP16 モデルを
ダウンロードします（`-DVDC_FETCH_DEPTH_MODEL=OFF` でモデルをスキップします）。すべてのダウンロードはハッシュ検証されます。
シェーダーは実行時にコンパイルされるため、シェーダーツールチェーンは不要です。FidelityFX SDK v1.1.4 のヘッダーと署名済み
`amd_fidelityfx_dx12.dll`（MIT）も同様に AMD の GitHub リポジトリからダウンロードされます。`-DAPP_EDITION_AMD=ON` で Radeon 版
（FSR ホスト方式、パッケージに NVIDIA 専用ファイルなし）をビルドします。既定は GeForce 版です。DLSS 5 ランタイムはビルドの一部ではなく、
リリースワークフローが `runtime-310.8` リリースから 2 つのビルドをアーカイブに入れます。

## アーキテクチャ

<details>
<summary>パイプラインと設計メモ</summary>

```
VRChat Stream Camera ──Spout──▶ D3D11on12 receive ──▶ convert (sRGB / resize)
      ▶ NVIDIA Optical Flow (forward + backward) / block matching ──▶ motion vectors + confidence
      ▶ Depth Anything V2 (ONNX Runtime DirectML, every N frames) ──▶ normalized depth, reprojected in between
      ▶ [DLAA] ──▶ DLSSNR (nvngx_dlssnr.dll) ──▶ composite / compare ──▶ preview + PNG capture
Video file ──Media Foundation──▶ decode (GPU) ──▶ same pipeline, one frame at a time ──▶ MP4 (H.264 / HEVC + AAC) or PNG sequence
```

本アプリケーションは、DLSS 5 ニューラルレンダリングスニペットを NGX ランタイムの外側でホストします。DLL を直接読み込み、
そのモジュール名チェックを満たし、`DLSSNR.*` NGX パラメーター規約を使って D3D12 キュー上で機能を作成・評価します
（`src/ngx/DlssnrFeature.cpp`）。パラメーターは RenoDX の DLSS 5 アドオンが公開しているものと同じ一式です。

ガイダンスの方式は動画入力向けに組まれています。同解像度の SDR 入力、順方向と逆方向のベクトルが一致しない箇所で
信頼度を下げるハードウェアオプティカルフロー、Depth Anything V2 による単眼深度を（2 / 98 パーセンタイルで）反転相対深度に
正規化し推論の合間はモーションベクトルに沿って移動させたもの、そしてフレームごとの履歴リセットなし、という構成です。
すべて独立した MIT 実装です（`src/gfx/Pipeline.cpp`、`src/gfx/DepthEstimator.cpp`、`src/gfx/Shaders.cpp`）。
オプティカルフローエンジンは専用のネイティブ D3D11 デバイス上で動作し、フレームとベクトルは共有フェンスで順序付けられた
NT ハンドル共有テクスチャを通して D3D12 に渡されます（`src/gfx/NvOpticalFlow.cpp`）。

Radeon カードでは FSR ホスト方式（`src/gfx/FsrHost.cpp`）が DLSS 5 機能の代わりを務めます。FidelityFX API の FSR 3.1 アップスケーリング
コンテキストが同じ色・深度・モーション入力でネイティブサイズで動作し、別プログラムである DLSS-NR-on-AMD が外側からそのコンテキストに
取り付いて、出力にニューラルパスを適用します。

2 つのスレッドが GPU を共有します。処理スレッドは Spout レシーバー（またはファイル）、パイプライン、専用の D3D12 キューを持ち、
インターフェーススレッドはウィンドウ、ImGui、高優先度のプレゼントキューを持ちます。完成した画像はキュー間のフェンス待機を伴う
表示バッファを通して受け渡されるため、プレビューは常に最新の完成フレームを表示し、ウィンドウがニューラルパスを待つことは
ありません（`src/core/App.cpp`、`src/gfx/Device.cpp`）。静止画は WIC でデコードされ（EXIF の向きを適用）、一度だけ
アップロードされて、時間方向のネットワークが安定するまで同じパイプラインをゼロモーションで数パス通ります。

動画ファイルは、Media Foundation のソースリーダーが専用スレッドでデコードし（DXGI デバイスマネージャー経由のハードウェア
デコーダー、ソフトウェアへのフォールバックあり）、短いフレームキューに入れます。処理スレッドはパイプラインに 1 フレームずつ渡し、
そのフレームの結果の読み戻しを要求します。読み戻しはフレーム順に集められてライターに渡されるため、ニューラルパスが
フレーム間隔より長くかかってもフレームの欠落や重複は起きません。ライターは専用スレッドで各フレームを NV12 に変換し、
デコードした音声サンプルとともに Media Foundation のシンクライター（可能ならハードウェアエンコーダー）に送ります
（`src/core/VideoSource.cpp`、`src/core/VideoWriter.cpp`）。

</details>
